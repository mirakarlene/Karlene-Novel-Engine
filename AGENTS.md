# Инструкции для ИИ-агентов

Эти правила действуют для всего репозитория Karlene Novel Engine.

## Дизайн и структура UI

- Сохраняйте существующий дизайн и структуру интерфейса. Менять их можно только по явно сформулированному требованию пользователя, в пределах перечисленных им экранов и элементов.
- Не считайте задачи по исправлению ошибок, рефакторингу, оптимизации или добавлению функций разрешением на сопутствующий редизайн.
- Без явного требования не меняйте расположение и иерархию панелей, состав и порядок элементов, навигацию, размеры окон и контролов, отступы, шрифты, цвета, темы, подписи, значки и визуальное поведение.
- Не заменяйте таблицы плитками, встроенные панели отдельными окнами или существующий способ взаимодействия другим по собственной инициативе.
- Разрешение на одну правку UI не распространяется на соседние элементы или другие экраны. Не добавляйте визуальные «улучшения» заодно.
- При просьбе вернуть прежний вид найдите соответствующую версию в истории Git и восстановите указанные пользователем параметры. Не придумывайте новый вариант вместо восстановления.

## Неоднозначные требования

- Если требование допускает разные варианты дизайна, структуры UI или поведения, сначала задайте пользователю уточняющий вопрос и предложите конкретные варианты с кратким объяснением различий.
- Не выбирайте вариант самостоятельно и не считайте отсутствие ответа согласием. До ответа не реализуйте зависящую от него неоднозначную часть задачи; работу с однозначными независимыми частями можно продолжать.
- Если новая функция не помещается в текущую компоновку, объясните конкретную проблему и предложите варианты размещения. Не уменьшайте весь интерфейс, не переносите элементы и не добавляйте страницы или окна без согласованного требования.
- Различайте отображение структуры проекта и операции с файлами на диске. Просьба сгруппировать файлы в интерфейсе не разрешает физически перемещать или переименовывать их.

## Проверка изменений UI

- Ограничивайте diff согласованными изменениями. Сохраняйте остальные экраны и элементы в прежнем виде.
- Проверяйте затронутый экран при обычном и минимальном поддерживаемом размере окна: подписи должны помещаться, элементы не должны перекрываться или обрезаться, а навигация — сохранять согласованное поведение.
- Для восстановления размеров сравнивайте результат с исходной версией, для новых согласованных элементов — с требованиями пользователя. Не исправляйте найденные посторонние особенности дизайна без отдельного согласования.
- В описании результата и PR перечисляйте изменённые экраны и поведение, выполненные проверки и оставшиеся неоднозначности, если они есть.
