# Karlene Novel Engine

WPF-приложение для создания и запуска визуальных новелл на Lua/KRL. Для сборки требуются Windows и стабильный .NET 10 SDK (10.0.100 или новее в ветке 10.0). `global.json` выбирает последнюю установленную стабильную версию SDK 10.0.

## Сборка и запуск

```powershell
dotnet build KNE.sln
dotnet test KNE.sln
dotnet run --project KNE.csproj
```

Для запуска готовой сборки без SDK требуется .NET Desktop Runtime 10 для Windows соответствующей архитектуры. Приложение и тесты используют `net10.0-windows`.

Исходники сгруппированы в `src`; `KNE.csproj`, решение и точка входа `App.xaml` находятся в корне. Команды сборки и запуска выше остаются актуальны.

| Каталог | Содержимое |
| --- | --- |
| `src/Editor` | Рабочее окно, редактор сценариев, каталог блоков, оформление, диалоги и тестирование сцен |
| `src/Language` | Lua/KRL, подсветка, отступы, модель и компилятор блок-схем |
| `src/Runtime` | Исполнение, планировщик, профили, состояние, диагностика, плагины и отдельный worker |
| `src/Player` | Окно игры и его действия |
| `src/Rendering` | Фоны, экраны, игровой UI и эффекты текста |
| `src/Projects` | Создание, загрузка, конфигурация и файлы проектов |
| `src/Analysis` | Статический анализ и проверка синтаксиса |
| `src/Infrastructure` | Настройки пользователя, пути, редактор и журнал |
| `Resources`, `tests/KNE.Tests` | Локализация и проверки |

Публикация для Windows x64 с установленным Desktop Runtime:

```powershell
dotnet publish KNE.csproj -c Release -r win-x64 --self-contained false -o artifacts/publish/win-x64
```

## Работа с проектом

«Создать проект» предлагает две горизонтальные карточки с примером кода и связкой блоков. Традиционный способ создаёт `game/scenes/main.krl`, визуальный — готовую редактируемую `game/scenes/main.knegraph` с одной функцией `main`. Выбор сохраняется в `project.json` как `authoring_mode`; другие сцены можно создавать обоими способами. Созданный сценарий сразу открывается в редакторе. «Открыть проект» принимает папку с project.json. На главном экране сохраняются восемь последних проектов.

На втором шаге создания выберите размер окна по миниатюрам: 1920×1080 Full HD (рекомендуется), 1280×720 HD, 2560×1440 QHD, 1024×768, 800×600, 2560×1080 UltraWide или 1080×1920 для вертикального чтения. «Свой вариант» принимает целые значения ширины 640…3840 и высоты 480…2160. Миниатюры сохраняют пропорции и относительные размеры. Здесь же выбираются графический API (автоматически / OpenGL / Vulkan), лимит FPS (30 / 60 / 144 / без ограничений) и одна из пяти палитр игры с образцами цветов. По умолчанию установлены Full HD, автоматический API, 60 FPS и фиолетовая палитра; подсказка «Если не знаете, оставьте по умолчанию» помогает с графикой. Кнопка «Назад» сохраняет выбор. Настройки записываются в `engine/window.json`, `performance.json` и `theme.json`; тема самого редактора не меняется. Старые проекты сохраняют прежние размеры.

Дерево показывает папки с файлами, таблица — список файлов. Поиск без учёта регистра фильтрует оба представления по имени и относительному пути; допустимы разделители / и \. Внешние изменения подхватываются автоматически после короткой задержки. «Обновить» позволяет перечитать проект вручную; перед запуском конфигурация также перечитывается.

Таблица доступна только для просмотра. Создание, копирование, переименование и удаление выполняются через кнопки и меню действий. Существующие файлы не перезаписываются. Для смены точек входа сначала измените project.json: удаление и переименование активных точек входа и самой конфигурации запрещены. Отсутствующая точка входа не мешает работе с обычными файлами. Символические ссылки и junctions не поддерживаются.

При первом создании проекта выберите родительскую папку хранилища и его имя (по умолчанию `projects`). Новые проекты создаются внутри этой папки; повторно выбирать путь для каждого проекта не нужно. Путь меняется в «Настройки → Хранилище проектов» под настройкой внешнего редактора. KNE обнаруживает только непосредственные папки проектов в выбранном хранилище, без обхода дисков и вложенных каталогов. На стартовом экране список обновляется каждые пять секунд. Удалённые, перемещённые и находящиеся вне текущего хранилища записи истории остаются затемнёнными: щелчок показывает предупреждение и не пытается открыть их. Существующие проекты автоматически не перемещаются; их по-прежнему можно открыть вручную.

На карточке проекта показаны путь и местное время последнего успешного открытия. Полный путь доступен также в подсказке. Для старых записей без времени показано «Ещё не открывался в KNE». Крестик убирает запись из списка, сохраняя файлы; автоматическое обнаружение не возвращает скрытую запись. Открытие этой папки вручную снова добавляет её в список и обновляет время.

Настройки разделены на две группы: «Проекты» содержит путь к текстовому редактору и хранилище проектов, «Дизайн KNE» — имя пользователя, тему, летающие объекты и доступность блоков. На небольшом экране содержимое прокручивается, а «Сохранить» и «Назад» остаются доступны внизу окна.

При первом запуске используется фирменная тема «KNE · акварель»: фиолетовый акцент `#7C5CFF`, мягкий розовый и градиент от фиолетового к чёрному на главном экране. Сохранённые ранее светлая и тёмная темы остаются выбранными. В «Настройки → Дизайн KNE → Тема оформления» также доступны «Розовый кварц», «Ночной океан», «Лесной туман», «Тёплый янтарь», «Лавандовый рассвет», «Полночь», «Вишнёвый бархат», «Песчаный берег» и «Северное сияние». Добавлены также «Сапфировая ночь», «Персиковый рассвет», «Графит», «Мятный сад» и «Сливовый бархат». Все семнадцать палитр находятся в `src/Editor/Themes/Theme.xaml`; интерфейс получает цвета через `DynamicResource`. Переключение сразу меняет редактор, вкладки, каталог блоков, поля и палитру кода; «Сохранить» или «Назад» сохраняет выбор для следующего запуска. Оформление самой игры задаётся проектом и от темы KNE не зависит.

Увеличенные по высоте карточки сохраняют пропорции миниатюр без растягивания. Шесть карточек доступности показывают обычное зрение, протанопию, дейтеранопию, тританопию, ахроматопсию и высокий контраст. Миниатюры используют цветовую симуляцию (для первых трёх нарушений — матрицы [Machado et al., 2009](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html) в линейном sRGB). Сам редактор получает адаптированную палитру категорий, а не фильтр всего окна. При любом режиме кроме обычного у категорий, карточек каталога рядом со звездой и блоков схемы появляются различимые значки: облачко реплики, шестерёнка логики, глаз визуала и другие. Высокий контраст усиливает рамки; выделение блока сохраняет отдельную рамку. Режим применяется сразу, сохраняется вместе с настройками и не изменяет файлы проекта или внешний вид игры.

Заголовок главного экрана — `Karlene Novel Engine` с векторной акварельной фактурой и независимым плавным покачиванием букв. В «Настройки → Имя пользователя» можно указать имя для приветствия «Добро пожаловать, …»; пустое поле возвращает «Добро пожаловать в KNE». Главная кнопка использует фирменный фиолетовый; наведение на кнопки плавно меняет фон за 220 мс, обратный переход также анимирован. Стили вкладок учитывают выбранное и неактивное состояние, подписи комбобоксов отображают название варианта вместо имени типа данных.

Полупрозрачные пузыри главного экрана медленно поднимаются и отталкиваются от курсора, не перехватывая нажатия. В группе дизайна их можно заменить звёздами, лепестками, кристаллами или светлячками; движение и взаимодействие с курсором сохраняются. Анимации используют ограниченный таймер около 30 кадров/с и останавливаются при переходе к проекту/настройкам, сворачивании, выгрузке и закрытии окна. При отключённой анимации элементов управления в Windows логотип и объекты остаются статичными.

Неизменяемый рисунок каждой буквы и летающего объекта кешируется с двойной плотностью пикселей устройства; движение меняет только положение рисунка. Смена палитры, вида объекта или необходимой плотности логотипа обновляет кеш. Исходные контуры, цвета, количество объектов и движение пузырей сохранены; возможно отличие сглаживания на границах рисунка. Текст и блоки редактора остаются векторными. Для локального сравнения снимков, времени 40 кадров и выделений памяти в тестовом WPF-рендерере задайте `KNE_WELCOME_PROBE` как путь к каталогу вывода и запустите `WelcomeRenderTests`; это измерение декоративных элементов, а не FPS всего приложения.

«Помощь» открывает в браузере локальный HTML-справочник по каждому блоку и его параметрам. Файл `%LOCALAPPDATA%\KNE\help\blocks.html` обновляется при открытии справки из текущего каталога движка; интернет не нужен.

«Главный экран» закрывает текущий проект с вопросом о сохранении изменённых вкладок и оставляет KNE открытым. Можно сохранить, отказаться от изменений или отменить переход; ошибка сохранения сохраняет проект открытым. «Сохранить всё и выйти» сохраняет вкладки и закрывает программу.

Настройки редактора, тема, хранилище и история проектов сохраняются в %LOCALAPPDATA%\KNE\settings.json. Пустой путь к редактору означает Блокнот. Старый EditorPath из KNE.dll.config читается при первом запуске.

## Код и блок-схемы

Раздел «Вычисления» расположен между «Потоки» и «Асинхронность». Все 17 блоков записывают число в выбранную переменную `state`. Операнды принимают числа с точкой и выражения, например `score * 2`, `state.score + 5`, `clamp(score, 0, 100)`. Разрешены `+ - * / % ^`, скобки и функции `abs`, `sqrt`, `sin`, `cos`, `tan`, `floor`, `ceil`, `round`, `pow`, `mod`, `min`, `max`, `clamp`, `lerp`, `remap`. Произвольный Lua-код в выражениях не выполняется. Переменные должны уже содержать числа; строки вроде `"7"`, `nil`, логические значения, деление на ноль и бесконечный результат вызывают ошибку с исходным ID блока. Арифметика использует вещественные числа, включая целые Lua из `state`, чтобы не допускать целочисленного переполнения.

Тригонометрия принимает радианы. `round` округляет половины от нуля, `floor` — к −∞, `ceil` — к +∞. `lerp(A,B,t)` принимает коэффициент 0–1 и вычисляет один шаг: для перехода за время меняйте `t` в цикле с паузой. `remap(value,oldMin,oldMax,newMin,newMax)` допускает обратные диапазоны и экстраполяцию; исходные границы не могут совпадать. Константы: `pi`, `tau`, `e`, `phi`, `half_pi`, `sqrt2`.

«Продвинутая случайность» содержит таблицу значений и относительных весов: `0.6` / `0.4` и `6` / `4` дают одинаковые 60% / 40%. Значения могут быть дробными или выражениями; веса неотрицательные, нулевой вес исключает строку. Допускается 1–100 строк с хотя бы одним положительным весом. Случайные выборы воспроизводятся при загрузке сохранения.

«Формула» хранит название и до 64 шагов `имя = выражение`. Шаг видит переменные проекта и результаты предыдущих шагов; последний результат записывается в выбранную переменную `state`. Кнопки копирования/вставки переносят рецепт в другой блок; «Найти формулы в проекте» предлагает рецепты из сохранённых схем и текущего открытого черновика. Вставка создаёт независимую копию, сохраняя выходную переменную и связи целевого блока. Изменение копии не затрагивает оригинал.

Поиск файлов находится над деревом в левом сайдбаре. Справа сверху расположены вкладки открытых файлов: имя с расширением, `*` при изменениях и крестик закрытия. Повторное открытие файла выбирает уже существующую вкладку. Переключение сохраняет черновики, историю отмены, выделение, масштаб и положение схемы. При закрытии изменённой вкладки можно сохранить изменения, отклонить их или отменить закрытие; ошибка сохранения оставляет вкладку открытой. «Сохранить всё и выйти», анализ и запуск проекта сохраняют все открытые вкладки. Сохранение и обновление списка файлов сохраняют раскрытые папки и выбранный файл дерева.

В блок-схеме щёлкните пустое полотно и нажмите **Tab**, чтобы найти уже созданный блок по названию, ID, тексту или ресурсу. Стрелки ↑/↓ выбирают результат, Enter центрирует и выделяет блок без изменения масштаба. Esc закрывает поиск. Tab в коде и полях свойств сохраняет обычное поведение.

При открытии проекта KNE проверяет формат `.knegraph`. Для старых блоков «Условие» и распознанного регистра JSON-полей предлагается миграция с резервной копией точных исходных файлов в `.kne-backups/migration-…/<путь исходного файла>.original`. Резервные копии исключены из списка игровых сценариев. Старые условия становятся «Ветвлением» с прежним сравнением значения и связями; создать legacy-блок заново нельзя. Неизвестные поля, типы блоков и неподдерживаемые версии схемы требуют совместимой версии KNE: миграция для них недоступна, данные не отбрасываются. Можно отменить открытие или создать отдельный новый проект. Повреждённый JSON и ошибки значений показываются как ошибки данных, а не как обновление движка. `Width` и `Height` поддерживаются текущим форматом.

Поиск над деревом обозначен полупрозрачным «Поиск...». Таблица файлов использует выбранную тему, тонкие границы шапки и строки без боковых кнопок выделения. `.knegraph` определяется как «Блок-схема». В меню каждой строки доступны «Редактировать», «Переименовать», «Дублировать», «Переместить» и «Удалить». «Редактировать» открывает Lua/KRL и блок-схемы во внутренней вкладке, остальные файлы — в редакторе из настроек. Двойной щелчок по строке сценария или заголовку файла в дереве открывает именно этот файл; пустое место, шапка и меню действий не открывают ранее выделенный файл. Кнопка «Оформление» открывает визуальный редактор экранов игры.

«Переместить» предлагает выбрать полный новый путь файла внутри проекта. Родительский каталог должен существовать; существующий файл не перезаписывается. Открытый сценарий сначала нужно закрыть. Конфигурация и точки входа защищены от перемещения, переименования и удаления. Ссылки на прежний путь в сценариях автоматически не переписываются.

Полосы прокрутки скрыты во всём интерфейсе, включая код, свойства, выпадающие списки и игровой журнал; прокрутка колёсиком, клавиатурой и переход к каретке сохраняются. Для горизонтальной прокрутки используйте Shift + колёсико; если область прокручивается только по горизонтали, достаточно обычного колёсика. В каталоге все 13 разделов помещаются в одной узкой колонке с промежутками. При наведении карточка или раздел плавно заполняется цветом своей категории справа налево; цвет учитывает выбранный режим доступности. Размеры карточек и сетка 4×3 сохранены.

Режим кода использует AvalonEdit с палитрой выбранной темы в стиле VS Code: ключевые слова, управление потоком, функции Lua/KRL, переменные, строки, числа и комментарии имеют разные цвета. Длинные строки и комментарии Lua с разделителями `[=[...]=]` учитываются отдельно. Парные `()`, `[]`, `{}` окрашиваются по глубине вложенности; у курсора подсвечиваются обе скобки, несовпадающие отмечаются красным. Показаны номера строк и текущая строка. Сгенерированный код блок-схемы получает ту же подсветку и остаётся только для чтения.

Tab вставляет ровно четыре пробела. Для выделенных строк Tab добавляет отступ, Shift+Tab убирает до четырёх ведущих пробелов (или один существующий tab). Enter сохраняет отступ и добавляет уровень после `function`, `then`, `do`, `repeat` и открытых скобок; строка с `end`, `else`, `elseif`, `until` или закрывающей скобкой при переносе выравнивается по началу блока. Enter внутри пустой пары скобок оставляет отдельную строку для содержимого. Скобки и кавычки дополняются автоматически, могут обрамлять выделение; Backspace в пустой паре удаляет её целиком. Изменение отступа и вставка пары отменяются одним действием. При открытии файла существующие tab и окончания строк сохраняются.

«Новая блок-схема» создаёт отдельный `.knegraph` внутри проекта с готовой цепочкой «Начало → Реплика → Конец». Переключатель «Код / Блок-схема» находится справа внизу области редактирования. Для графа «Код» показывает сгенерированный Lua только для чтения; «Копия как KRL…» создаёт новый файл для ручного редактирования. Произвольный Lua/KRL обратно в блоки не преобразуется.

«+ Добавить блок» открывает полупрозрачный каталог в основном окне: слева группы команд, справа карточки доступных команд и поиск по выбранной группе. Выбор создаёт блок в центре видимой области с учётом сдвига и масштаба. Закрытие, Esc и щелчок по затемнению отменяют выбор без изменения схемы. Второй блок «Начало» недоступен. Существующие схемы и идентификаторы блоков сохраняются.

Перетаскивайте блоки за заголовки, а края и углы — для изменения размера. У блоков есть рамка и мягкая тень цвета группы. Порты входа находятся слева, выходы — справа. Соединение можно протянуть между портами в любом направлении: стрелка всегда идёт от выхода ко входу. Прежнее соединение двумя щелчками сохраняется; правая кнопка по выходу удаляет связь, Esc отменяет незавершённое соединение. Стрелки привязаны к портам и перестраиваются при переносе и изменении размера.

Зажмите левую кнопку на пустом полотне для выделения областью: выделяются все пересекающиеся с ней блоки. Ctrl/Shift добавляют блоки к выделению; Ctrl по выделенному блоку снимает его выделение. Заголовок переносит всю выбранную группу. Ctrl+C копирует, Ctrl+V вставляет группу в центр обзора, Ctrl+D дублирует со сдвигом, Ctrl+Z отменяет, **Ctrl+X повторяет** последнее действие (Ctrl+Y также работает). В текстовых полях сохраняются обычные сочетания, включая вырезание текста Ctrl+X. Внутренние связи при копировании сохраняются, внешние отсоединяются; новые блоки получают новые ID. Блок «Начало» не копируется, чтобы точка входа оставалась единственной. Групповой перенос и вставка отменяются одним действием.

Свойства выбранного блока редактируются справа и применяются кнопкой «Применить свойства», при сохранении или смене выбранного блока. Варианты выбора, case и названия параллельных веток задаются по одному на строку; связи сохраняются по позиции строки. Масштаб меняется ползунком, кнопками «−»/«+» с шагом 10% или Ctrl+колесом. Зажмите правую кнопку на свободном полотне или карточке и перетаскивайте обзор. Полос прокрутки нет; границы полотна расширяются за блоками, допускаются отрицательные координаты. Перемещение обзора и масштаб не меняют сценарий.

Каталог имеет постоянный размер и страницы по 12 карточек: 4 столбца и 3 строки. Размер карточек сохраняется; в небольшом окне прокручивается сам каталог. Поиск и смена группы возвращают первую страницу. Звезда в углу добавляет карточку в «Избранное», не создавая блок. «Недавнее» хранит 12 последних разных блоков, начиная с последнего использованного. Эти списки сохраняются в профиле пользователя в `block-library.json`; звёзды и недавние записи старого «Условия» переносятся на «Ветвление». «Плагины» всегда последняя группа.

«Ветвление» находится в нарративе и сравнивает переменную с заданным значением, «Условие» в логике сравнивает две переменные. Форма карточек прежняя. Входы и выходы называются портами. У комментария нет портов: это отдельная заметка автора. При открытии старой схемы связи через комментарии перенаправляются на следующий исполняемый блок, а заметки сохраняются отдельно. Титр выводится вне диалогового окна и остаётся до следующего титра; пустой текст скрывает его. Для отдельной заставки подключите после титра паузу или реплику.


«Потоки» находится после «Звук», перед «Вычисления» и «Асинхронность». Прежние блоки перехода и вызова, их связи, избранное и недавние записи автоматически получают новую группу. «Подсистема» ссылается на `.knegraph` относительно корня проекта. На карточке показано имя файла. Двойной клик или «Открыть / создать подсистему…» открывает файл в отдельной вкладке, а отсутствующий создаёт с уникальным именем функции. Черновик родительской схемы остаётся во вкладке. Все выходы «Конец» при вызове как подсистемы возвращают в родителя; обычный вызов публичной функции этого файла сохраняет прежнее поведение. Включённое «Ждать полного завершения подсистемы» приостанавливает родителя; выключенное запускает её как фоновую асинхронную ветку. В фоне визуальные и звуковые команды работают, реплики идут в консоль; выбор и ввод игрока требуют режима с ожиданием. Самоссылки и рекурсивные вызовы ограничены общей глубиной 64; число одновременных веток ограничено движком.

«Триггеры» находится между «Асинхронность» и «Конфигурации». У триггера есть вход и выход. Если вход подключён к предыдущему блоку, ветка доходит до триггера, ждёт подходящее событие и продолжает с выхода; до посещения блока событие не отслеживается. Триггер без входящей связи сохраняет прежний режим независимого обработчика: регистрируется при входе в функцию и снимается после выхода из неё. Обработчик обычно завершают через «Конец → Завершить ветку / вернуться». Пока обработчик занят, он повторно не запускается; галочка «Сработать только один раз» отключает дальнейшие срабатывания. События и занятость обработчиков восстанавливаются при загрузке сохранения и возврате в тесте сцены.

Клавишу можно записать вручную или выбрать кнопкой «Нажать нужную клавишу…». Для комбинации нажмите и отпустите все нужные клавиши, например `Ctrl+Shift+E`; порядок, регистр и левая/правая сторона модификатора не важны. Автоповтор удерживаемой клавиши не запускает обработчик повторно. При наборе текста в игровом поле ввода или консоли клавиатурные триггеры не перехватывают ввод. ID встроенных кнопок: `next`, `save`, `load`, `auto_save`, `pause`, `choice:1` … `choice:20`, `input_submit`, `input_cancel`. У кнопок экранов ID имеет вид `screen:Название экрана/ID элемента`; можно выбрать его из списка. Зарегистрированный триггер перехватывает соответствующий клик или клавишу вместо стандартного действия. Хотспоты задаются прямоугольником в логической игровой области 1280×720 и масштабируются вместе с окном; правая/нижняя границы не входят в область. Закрытие текстового окна включает скрытие диалога игровым интерфейсом и команду «Очистить текст». Клавиатура, хотспоты и кнопки дополнительных экранов доступны также в «Тестировать сцену».

В коде доступны `kne_subsystem("game/scenes/subsystem.knegraph", true)` (второй аргумент — ждать завершения) и `kne_on_event('{"kind":"key","keys":"Ctrl+E","once":false}', function() ... end)`. Параметры других событий: `kind="button", button="next"`; `kind="hotspot", x=100, y=100, width=200, height=100`; `kind="text_closed"`.

Новый «Конец» по умолчанию возвращает в главное меню. «Специальный экран» требует название из «Оформления»; «Закрыть игру» закрывает окно игры. «Завершить ветку / вернуться» заканчивает тело цикла/параллельную ветку или возвращается из `call`. Старые документы без настройки конца сохраняют прежний возврат. В тесте сцены все варианты конца показывают служебный экран завершения и не закрывают редактор.

Переменные хранятся в `state`: укажите имя, тип и значение. Числа вводятся с точкой, флаги — `true`/`false`. Switch выбирает case по типизированному значению, иначе идёт по выходу по умолчанию. While повторно проверяет сравнение. For Each перебирает массив в `state`, записывая текущий элемент и индекс с 1 в указанные переменные. Действия до цикла должны создать массив, например `state.items = {"A", "B"}` в инициализации; вложенные JSON-массивы поддерживаются в `engine/state.json`. Словари и массивы с пропусками отвергаются. Случайное значение при целых границах включает A и B, при дробных выдаёт дробное число; seed сохраняется при восстановлении.

У циклов есть «Тело» и «Далее», у Try/Catch — тело, обработчик и продолжение, у Switch и параллельных блоков — выходы веток. Внутреннюю ветку подключите к «Далее» управляющего блока или завершите через «Конец → Завершить ветку / вернуться». Обратные связи для циклов рисовать не нужно. Try/Catch записывает текст ошибки в выбранную переменную и выполняет обработчик, затем продолжение. Он также перехватывает ошибку ожидаемой параллельной ветки, отменяя её соседей.

«Параллель» совместно выполняет ветки и ждёт все; интерактивные реплики и выборы этих веток показываются по очереди. «Асинхронность» сохраняет ID фоновой группы и сразу продолжает основную ветку; Join ожидает этот ID. Фоновые ветки продолжаются, пока игрок читает реплику. Их реплики попадают в журнал, а интерактивный выбор в фоне сообщает ошибку — используйте «Параллель». Пауза и таймер ждут время в секундах без блокировки интерфейса. Ожидание условия проверяет сравнение после обновлений, таймаут 0 означает без ограничения. Часы приостанавливаются в меню; «Остановить» прерывает и фоновое выполнение, включая цикл с отключённым hook. Завершение и корневой goto отменяют незавершённые фоновые задачи. Сохранения и возврат повторяют записанные шаги времени.

Перемещения задаются в пикселях сцены, масштаб камеры 1 означает 100%. Анимации: pulse, rotate, fade_in, fade_out и none; задаются объект, длительность и сила. Вспышка принимает цвет #RRGGBB/#AARRGGBB. Снимок фрейма показывает конечное неподвижное состояние эффекта, тест сцены проигрывает анимацию.

«Показать экран» принимает название из «Оформления», прозрачность 0–1 и слой: `main` рядом с фоном и персонажами либо `overlay` выше игрового интерфейса. Названия экранов уникальны без учёта регистра и крайних пробелов. Старые ссылки по ID продолжают работать, если нет совпадающего названия. Пустое название или кнопка «Назад/Вернуться» скрывает показанный экран. Пример: `show_screen('Галерея', 0.8, 'overlay')`. «Удалить все фоны» (`clear_backgrounds()`) убирает также стандартный фон и сбрасывает его анимацию; «Удалить все спрайты» (`clear_sprites()`) убирает персонажа и его анимацию. Следующий показ фона или «Скрыть фон» возвращает обычный режим оформления.

Группа «Конфигурации» меняет игровой UI во время прохождения блока. У текстового окна и кнопок доступны X/Y, ширина/высота, семейство/размер/насыщенность шрифта, цвета текста и фона, прозрачность, скругление, текстура, четыре отступа, выравнивание текста и привязки к краям. X/Y — отступы от выбранных краёв; используются координаты игровой области. Пустая текстура оставляет цветной фон движка, своя картинка импортируется в `game/ui` без изменения оригинала. Семейство шрифта должно быть установлено на устройстве игрока. Конфигурации сохраняются в истории, восстанавливаются при загрузке и возврате, сбрасываются при новом запуске. Обработчики игровых кнопок сохраняются. Для кода используется `configure_ui('dialogue', '{"width":900,"font_size":28}')`; другие цели: `choice`, `next`, `save`, `load`, `auto_save`, `pause`.

В группе «Плагины» показано предупреждение: «Внешние файлы, особенно скачанные из интернета, могут иметь неожиданные последствия, работайте с этим на свой страх и риск». `include_lua('game/plugins/helper.lua')` и `include_cs('game/plugins/helper.cs')` выполняют подключение один раз за сессию. `run_script('game/scripts/custom.lua')` выполняет файл при каждом входе в блок; поддерживает `.lua`, `.krl` и `.cs`. «Скрипт» предлагает создать или выбрать файл внутри `game`, сохраняет путь в блоке и открывает внешний редактор из настроек KNE. Повторное открытие не заменяет содержимое. Подключение не требует установки .NET SDK у игрока; исходный C# компилируется в памяти. C#-файл должен содержать один открытый класс `IKnePlugin` с открытым конструктором без параметров:

```csharp
using System;
using KNE;

public sealed class ScorePlugin : IKnePlugin
{
    public void Execute(IPluginContext context)
    {
        context.Set("score", Convert.ToDouble(context.Get("score") ?? 0d) + 1);
        context.Log("Счёт обновлён");
    }
}
```

Контекст предоставляет скалярные значения `state` через `Get/Set`, журнал `Log`, `ProjectDirectory` и `CancellationToken`; используйте его только во время `Execute` и в том же потоке. Экземпляр C#-плагина переиспользуется до изменения исходника или перезапуска. Сторонние сборки/NuGet автоматически не подключаются. Плагины выполняются с правами текущего пользователя: отдельный игровой процесс позволяет остановить зависший код, но не является песочницей. Возврат и загрузка повторяют выполнение плагинов, поэтому их внешние побочные эффекты также могут повториться.

Аудиоканалы независимы: music, sfx, voice, ambient. Итоговая громкость умножает настройку игрока, громкость канала и общую громкость проекта. Музыка может повторяться, озвучка и эффекты — однократные; остановка одного канала не прерывает остальные. Пути ресурсов задаются от корня проекта. Пустой путь блока «Фон» или «Скрыть фон» возвращает оформление проекта.

Блок перехода завершает текущую ветку, блок вызова имеет выход «Далее» после возврата. В свойствах укажите имя функции, например `park`, без пути к файлу.

Поле «Функция» над полотном задаёт имя функции блок-схемы. Новый граф получает свободное имя `scene_имяфайла`, при совпадениях — суффикс `_2`, `_3` и далее. Чтобы граф стал стартом игры, назовите его функцию `main` и переименуйте прежнюю `main`. «Сделать главной» сохраняет путь файла с единственной `main` в project.json и проверяет это условие. Подсказки переходов различают `goto` (переход без продолжения текущей ветки) и `call` (возврат к следующей команде после завершения вызванной функции).

«Сохранить» или Ctrl+S сохраняет сценарий. Незавершённый граф разрешено сохранить как черновик. Перед предпросмотром кода, экспортом и запуском проверяются связи: ровно одно начало, обязательные выходы подключены, исполняемые блоки достижимы, произвольных циклических связей нет. До 500 блоков, до 20 вариантов/веток на блок; до 128 активных задач, до 10 000 итераций цикла. Превышение лимита сообщает ошибку с ID блока. «Отменить»/«Повторить» возвращают изменения графа; Ctrl+Z/Ctrl+Y работают на полотне, а в текстовых полях отменяют ввод.

Дерево файлов остаётся слева, код или блок-схема занимают всю высоту рабочей области. Выделение и ввод не запускают Lua. Две кнопки над редактором открывают отдельные окна и работают с несохранённой версией текущего документа. Фреймом называется отдельная реплика `d()` или выбор `choice()`, сценой — именованная функция.

«Предпросмотр фрейма» строит неподвижный снимок с фоном, персонажем и текстом в текущей функции. Для визуального блока без текста берётся следующий текстовый фрейм. Если до выделения есть развилка, сначала выберите путь; готовый снимок уже не интерактивен. Поиск ограничен 2000 шагами и таймаутом проекта. Анимация и звук в снимке не воспроизводятся.

«Тестировать сцену» начинает выбранную функцию после инициализации проекта, с настоящими репликами, выборами и анимацией оформления. `call` выполняет дочернюю функцию и возвращается; корневой `goto` проверяет цель и завершает тест перед переходом к следующей сцене. В конце появляется служебный полупрозрачный экран «Вы достигли конца сцены»: «Вернуться» восстанавливает предыдущий фрейм, «Начать заново» запускает функцию сначала. Этот экран создаётся только системой тестирования. Игра и тест не записывают общие сохранения; тест вообще не создаёт слотов. Возврат повторяет сделанные действия с тем же seed; сценарии должны оставаться детерминированными. Если исходники или начальное состояние изменились, сначала перезапустите сцену. Файловые и другие побочные эффекты Lua при повторе могут выполниться повторно. Звук тестирования отключён.

`engine/frame-ids.json` хранит числовые ID команд/блоков, включая текстовые фреймы. Есть номер внутри сцены и уникальный номер в игре: новые команды занимают минимальный свободный положительный номер, сохранившиеся сохраняют свои ID. Изменение строки кода может создать новую команду; перемещение блока не меняет его идентичность. Реестр обновляется при открытии проекта и сохранении, снимок сам его не записывает. Подсказка заголовка блока показывает ID; диагностика ошибки содержит ID сбойного блока и фрейма. Нетекстовые команды используют то же пространство номеров, поэтому первая реплика не обязательно имеет номер 1.

Кнопка «Внешний редактор» в режиме ручного кода сначала сохраняет документ, затем открывает его программой из настроек KNE. Конфликт сохранения останавливает открытие внешнего редактора.

При переключении сценария, закрытии редактора, выходе из проекта или приложения предлагается сохранить несохранённые изменения. Внешние правки не перезаписываются: при конфликте сохранение сообщает ошибку. Для графа можно экспортировать KRL-копию; для ручного кода скопируйте текст, затем закройте редактор с отказом от сохранения и откройте файл заново. Открытый сценарий нужно закрыть перед переименованием или удалением.

## Персонажи и нарративные команды

«Персонаж» в нарративе регистрирует профиль без изображения: ID из латинских букв, цифр и `_` (без цифры в начале и ключевых слов Lua), отображаемое имя, цвет имени, выравнивание текста, семейство и размер шрифта. Для изображения остаётся отдельный блок «Отобразить спрайт». Регистрация должна выполниться до реплики с выбранным профилем. Один ID нельзя зарегистрировать с разными параметрами; повтор той же регистрации допускается, например в цикле.

В «Реплике», «Авто-пропуске» и «Реплике с эффектом» можно написать имя вручную либо выбрать профиль кнопкой под полем. Выбор открывается в редакторе и включает профили блок-схем проекта, в том числе несохранённые изменения текущего документа. Ручная правка имени отключает ссылку на профиль. Пустое имя без профиля использует спикера по умолчанию, а если спикер не установлен — рассказчика. Кнопка «Рассказчик / мысль» и галочка «Рассказчик» явно отключают автоматического спикера для этой реплики. Профиль задаёт цвет имени, шрифт и выравнивание текущей реплики; следующая ручная реплика возвращается к обычному оформлению.

«Изменить персонажа» заменяет отображаемое имя, цвет, выравнивание и шрифт существующего профиля с тем же ID. Можно выбрать зарегистрированный профиль кнопкой и отредактировать параметры. Неизвестный ID вызывает ошибку; создание нового персонажа по-прежнему выполняет «Персонаж». Уже показанный фрейм сохраняет прежние параметры, следующие реплики получают изменения. В коде используется `update_character(json)` с теми же полями, что у `register_character(json)`.

«Установить спикера» / `set_speaker("alice")` назначает зарегистрированный профиль следующим репликам с пустым говорящим. «Сбросить спикеров» / `reset_speakers()` возвращает рассказчика. Явное имя или ссылка на другой профиль имеют приоритет. Настройка действует внутри текущей корутины: вызванная функция, переход `goto` и параллельные ветки наследуют её снимок. Правки в дочерней или соседней ветке не меняют спикера вызывающей ветки. Сохранения восстанавливают настройки повторным воспроизведением команд; новый запуск начинает без спикера.

«Ветвление» в нарративе сравнивает переменную `state` с постоянным числом, строкой или логическим значением. «Условие» в логике сравнивает текущие значения двух переменных. Оба блока сразу выбирают выход «Да» или «Нет», не создавая реплики и не ожидая ввода игрока. Старые нарративные условия переименовываются при чтении схемы; старые логические условия с постоянным значением сохраняют прежнее поведение и явно помечены как прежний формат.

«Пауза в тексте» удерживает предыдущую реплику указанное время; галочка разрешает или запрещает пропуск нажатием «Далее»/клавиши продолжения. «Очистить текст» очищает имя и текст мгновенно либо постепенно стирает целые символы за заданное время. «Авто-пропуск» показывает реплику и продолжает автоматически по таймеру; возможность пропуска по клику задаётся отдельно. Время считается игровыми часами: в меню паузы оно останавливается. При сохранении/загрузке и возврате восстанавливаются профиль, эффект и оставшееся время.

«Запись в консоль» выводит текст через `print()` без остановки на реплике. «Случайная ветка» имеет от 2 до 20 выходов с относительными весами: 60/40 и 3/2 дают одинаковые вероятности. Вес 0 исключает ветку; все веса не могут быть нулевыми. При восстановлении используется тот же seed, поэтому выбранная ветка воспроизводится.

«Реплика с эффектом» применяет эффект ко всему тексту. Доступны скорость, цикличность и два цвета для цветовых эффектов:

| Эффект | Вид |
| --- | --- |
| Дрожание / Shake | Мелкие быстрые смещения букв |
| Волна / Wave | Буквы поднимаются и опускаются синусоидой |
| Покачивание / Sway | Мягкие наклоны влево-вправо |
| Прыжки / Bounce | Последовательные подпрыгивания |
| Плавание / Float | Медленный дрейф с разными фазами |
| Взрыв / Explode | Разлёт от центра и возврат |
| Пульсация / Pulse | Синхронное изменение размера |
| Кручение / Spin | Вращение букв |
| Сжатие / Squash | Чередование сжатия и растяжения |
| Глитч / Glitch | Резкие смещения и двойники |
| Размытие / Blur | Изменение размытия букв |
| Растворение / Dissolve | Постепенное исчезновение |
| Печать хаосом / Scramble | Временные символы сменяются исходным текстом |
| Радуга / Rainbow | Перелив цветов по буквам |
| Пульсация цвета / Color Cycle | Переход между двумя цветами |
| Растекание / Drip | Капли цвета букв, нарисованные поверх шрифта |

Эффекты и стирание сохраняют целые текстовые элементы Unicode. «Предпросмотр фрейма» показывает неподвижное состояние, «Тестировать сцену» проигрывает движение. Отключение анимации в настройках сохраняет читаемый текст. Растекание использует векторные капли и не требует специального шрифта. Анимируются только символы видимой области; если одновременно видны больше 4096 текстовых элементов, показывается полный обычный текст, чтобы сохранить отзывчивость окна.

Те же команды доступны в Lua/KRL:

```lua
function main()
    register_character('{"id":"alice","name":"Алиса","name_color":"#FFCC88FF","text_alignment":"left","font_family":"Segoe UI","font_size":26}')
    kne_say(nil, 'Реплика из профиля', 'alice')
    text_pause(2, true)
    kne_say(nil, 'Волна', 'alice', '{"kind":"wave","speed":1.5,"loop":true}')
    clear_text(true, 0.5)
    kne_say(nil, 'Исчезнет через три секунды', nil, nil, 3, false)
    console_write('Сегмент завершён')
    local branch = kne_random_branch({60, 40})
    d(nil, 'Выбрана ветка ' .. branch)
end
```

## Импорт и анализ проекта

Внизу сгруппированы выход/сохранение, создание и импорт, список/обновление, анализ/запуск. «Сохранить всё и выйти» сохраняет открытый документ; конфликт сохранения оставляет окно открытым. «Импорт файла» копирует выбранный файл в указанный путь внутри `game`, не изменяя оригинал и не заменяя существующий файл.

«Импорт .rpy» и «Импорт .docx» открывают окно сравнения: оригинал слева, редактируемая адаптация в KRL справа. Обе функции экспериментальные; проверьте результат перед сохранением. RenPy поддерживает ограниченный набор label, реплик, меню и переходов, создавая функции с отдельным префиксом. Неподдерживаемые конструкции комментируются и перечисляются в предупреждениях; изображения и аудио импортируйте отдельно. DOCX читается без Word: абзацы становятся репликами рассказчика, оформление и встроенные объекты не переносятся. Сохранение требует отдельного пути внутри `game`; отмена не создаёт сценарий.

«Анализ проекта» сохраняет открытый документ и проверяет проект без выполнения его кода. Проверяется синтаксис Lua/KRL, конфигурация, функции `main`, переходы, связи графов, буквальные пути ресурсов, обязательные `nil`, пустые функции, очевидные бесконечные циклы и рекурсия без приостановки. Синтаксис компилируется в отдельном скрытом процессе с ограничением времени. Проверки предупреждений эвристические: вычисляемые пути, условия и значения требуют проверки в игре. Анализ не гарантирует обнаружение всех возможных зависаний и ошибок. По завершении создаётся уникальный TXT в `<проект>/reports` с файлами, строками, ID, временем и количеством ошибок/предупреждений; файл автоматически открывается редактором из настроек KNE.

## Оформление и настройки игры: engine

Новый проект содержит готовые `engine/window.json`, `theme.json`, `game.json`, `state.json`, `screens.json` и `engine/README.txt`, а также папку `saves`. Изменения оформления применяются при следующем запуске окна игры; настройки игрока сохраняются отдельно от авторских файлов engine.

По умолчанию окно имеет размер 1280×720, открывается по центру экрана и показывает главное меню «Начать игру / Продолжить / Настройки / Сохранения / Выйти». Сцена занимает всё окно: фиолетовый фон с циклическими синусоидами, персонаж и диалог поверх фона. Журнал и командная строка скрыты до F3. Escape открывает меню паузы, F11 переключает полноэкранный режим. «Продолжить» загружает автосохранение, а при его отсутствии — quick; экран «Сохранения» позволяет выбрать любой ручной слот. Новая игра из меню паузы требует подтверждения; последнее сохранение остаётся доступным.

В «Оформлении» предусмотрены «Главное меню», «Сцена · новелла», «Экран настроек», «Экран паузы» и «Экран сохранений». Добавляйте собственные экраны, меняйте имена и роли или удаляйте экраны вне геймплея. Служебные роли уникальны; удаление главного меню включает прямой запуск, а отсутствие настроек или сохранений отключает соответствующие кнопки. Игровая сцена и её сценарии редактируются через Lua/блоки.

Элементы на холсте 1280×720 можно перетаскивать и менять через свойства. Поддерживаются текст, кнопка, панель, изображение, переключатель и ползунок; на экране сохранений — список слотов и поле имени. Кнопкам задаются игровые действия или navigate с выбором целевого экрана; нельзя удалить экран с активными ссылками. Кнопки записи, загрузки и удаления выбранного слота тоже можно перемещать. Стрелки слоёв меняют порядок наложения. Для движения задаются начальный вектор смещения X/Y, порядок (шаг 0.12 с), дополнительная задержка, длительность и цикл туда-обратно. Выбранный вектор показан на холсте; «Просмотр движения» проигрывает анимацию. Есть отмена/повтор и проверка внешних изменений при атомарном сохранении.

Новый элемент сразу выделяется и имеет действие «Нет». Действие назначается отдельно в свойствах: переключатели поддерживают полный экран или анимацию, ползунки — громкость музыки или звуков. Элементы без действия не меняют состояние игры или настройки игрока.

Палитры: violet, ocean, rose, forest, amber и custom. Узоры: waves (циклические синусоиды), ornament (статический орнамент), grid, dots и none. Скорость и амплитуда настраиваются; собственное изображение заменяет узор. Настройки игрока позволяют менять громкость музыки/звуков, полный экран и отключать движение оформления. Они записываются в `saves/preferences.json`.

- `window.json`: `width`, `height`, `position` (`center` / `manual`), `left`, `top`, `mode` (`windowed` / `maximized` / `fullscreen`) и `resizable`. Координаты и размеры задаются в логических пикселях Windows (DIP); начальная ручная позиция ограничивается виртуальным экраном.
- `theme.json`: `font_family`, `background_color`, `pattern`, `pattern_color`, `background_image`, `accent_color`, `text_color`, `button_color`, `character_width` и секции `dialogue`, `menu`. В диалоге настраиваются `height`, `margin`, `padding`, `corner_radius`, `font_size`, `speaker_font_size`, `background_color`, `border_color`, `text_color`, `speaker_color`. В меню: `width` (240–560), `title_font_size`, `subtitle_font_size`, `alignment` (`left` / `center` / `right`), `overlay_color`.
- `game.json`: `main_menu`, `subtitle`, `start_label`, `continue_label`, `exit_label`, `auto_save`, `debug_enabled`, `execution_timeout_seconds` (1–3600). `main_menu: false` запускает сцену сразу; меню паузы остаётся доступным. `debug_enabled: false` отключает открытие отладки по F3.
- `state.json`: начальные переменные таблицы `state`: строки, конечные числа, логические значения и вложенные объекты до 16 уровней. Они загружаются до `gamelogic.lua`, который может переопределить значения. Массивы и `null` не поддерживаются.
- `screens.json`: версия 1, список экранов и их векторные элементы. Не более 32 экранов и 100 элементов на экран. Если задана секция `theme`, она имеет приоритет над `theme.json`; визуальный редактор сохраняет тему и экраны одним атомарным файлом. При наличии screens.json расположение и размеры элементов меню берутся из него, а цвет затемнения — из темы.

Например, замените окно диалога и стандартный фон в `engine/theme.json` (неуказанные поля сохраняют значения по умолчанию). После визуального сохранения те же поля редактируются в секции `theme` файла `engine/screens.json`:

```json
{
  "background_image": "game/backgrounds/title.png",
  "pattern": false,
  "dialogue": {
    "height": 220,
    "font_size": 26,
    "background_color": "#E6201630",
    "speaker_color": "#FFFFCC88"
  }
}
```

Пути изображений задаются от корня проекта. Поддерживаются PNG, JPG/JPEG, BMP и GIF; фон масштабируется с заполнением окна. `background(...)` перекрывает стандартный фон, `background(nil)` возвращает его. `set_bg_color(...)` заменяет узор и стандартное изображение сплошным цветом; возврат к цвету `background_color` восстанавливает оформление. Lua-команды размера и заголовка окна имеют приоритет над начальными настройками.

Некорректные настройки сообщаются с ошибкой до запуска игры. Отдельные отсутствующие файлы используют значения по умолчанию; проекты без всех пяти JSON-файлов сохраняют прежний запуск сцены без меню и размер 800×600. Старым проектам без screens.json готовые экраны создаются в памяти; их можно сохранить через «Оформление». Изменение темы, окна или меню не отменяет совместимость сохранений; изменение `state.json` — отменяет.

Отдельные окна тестирования используют оформление и пропорции игрового окна, размеры диалога и персонажа, пропуская главное меню.

## project.json

```json
{
  "metadata": { "name": "Моя новелла", "version": "1.0.0" },
  "game_info": { "title": "Моя новелла" },
  "entry_points": {
    "main_scene": "game/scenes/main.krl",
    "init_script": "game/scripts/gamelogic.lua"
  }
}
```

Пути задаются относительно корня проекта. Поддерживается старое поле name в корне JSON. Для старого шаблона, где указан game/scripts/game_init.lua, используется game/scripts/gamelogic.lua, если первый файл отсутствует. Ошибки JSON и отсутствующие явно заданные точки входа сообщаются пользователю.

## Диалоги и выборы

Игра всегда начинается с единственной глобальной функции `main()` в проекте. Она может находиться в любом Lua/KRL-файле или быть функцией блок-схемы. Перед ней выполняются скрипты инициализации. Возвращаемая из файла анонимная функция не заменяет `main`. Отдельный main.lua не требуется; `main_scene` в project.json сохраняет путь стартового файла для редактора и предпросмотра.

До показа главного меню проверяются все Lua/KRL/блок-схемы на диске. Два объявления `main`, в том числе в одном или неиспользуемом файле, заменяют меню и игру экраном «Ошибка игры» с файлами и строками объявлений. Отсутствие `main` и ошибка при запуске также показывают этот экран. На нём доступны копирование подробностей и выход; после исправления сценария откройте игру снова. Комментарии, строки, локальные функции и методы объектов не считаются глобальной точкой входа.

```lua
-- game/scripts/gamelogic.lua
state.score = 0
function process_command(command)
    print("Команда:", command)
end
```

```lua
-- game/scenes/main.krl
function main()
    d(nil, "Добро пожаловать!")
    d("Алиса", "Куда пойдём?")
    local answer = choice("Выберите маршрут", {"Домой", "В парк"})
    state.score = answer
    if answer == 2 then
        d("Алиса", "Идём в парк.")
    else
        d("Алиса", "Возвращаемся домой.")
    end
    d(nil, "Очки: " .. state.score)
end
```

d(speaker, text) приостанавливает сцену на реплике. Кнопка «Далее», пробел или щелчок по тексту продолжают сцену. choice(prompt, options) показывает от 1 до 20 непустых вариантов и возвращает индекс выбранного ответа, начиная с 1. Реплики и выборы работают внутри игровых сцен и вызываемых ими функций; d() вне корутины сцены пишет сообщение в журнал.

Для отладки доступна строка команд: Enter вызывает process_command(command), если такой обработчик объявлен. Команды выполняются последовательно.

## Экран ошибки игры

Ошибка сценария при запуске, после реплики, выборе ответа, выполнении команды отладки или восстановлении сохранения заменяет игру экраном «Ошибка игры» в том же окне. Игра, меню, звук, анимация и игровые действия останавливаются; доступны копирование отчёта и выход. Ошибочное действие не перезаписывает автосохранение или ручной слот.

Отчёт показывает название и заголовок проекта, его папку, исходный файл и строку, текст и тип ошибки, время возникновения с миллисекундами и часовым поясом, выполнявшееся действие, ОС с версией, имя устройства, архитектуру ОС и подробности стека. Информация сохраняется в момент ошибки в Lua-worker и передаётся в окно без изменения времени. Длинные пути и кириллица сохраняются полностью. Для ошибок JSON блок-схем показывается строка JSON; для ошибки выполнения графа строка относится к сгенерированному Lua, что отмечено в отчёте.

Если источник нельзя определить, например после принудительного завершения зависшего worker без Lua-стека, поля файла и строки явно помечены как неопределённые. Отмена по кнопке «Остановить» и ошибки чтения/записи файлов сохранений остаются уведомлениями и позволяют продолжить работу. Отчёт отображается локально и сам никуда не отправляется.

## Приоритет загрузки: init

Первым оператором Lua/KRL-файла можно поставить `init(приоритет)`. До него допускаются пробелы и Lua-комментарии. Приоритет — целое число от −10000 до 10000; меньшие числа загружаются раньше. При равенстве используется порядковое сравнение относительных путей с разделителем `/` (с учётом регистра, независимо от языка Windows). Например:

```lua
-- game/scripts/characters.lua
init(-20)
player_name = "Игрок"
```

```lua
-- game/scripts/gamelogic.lua
init(0)
print("Привет, " .. player_name)
```

`init_script` из project.json загружается всегда, с приоритетом 0 при отсутствии декларации. `engine/state.json` загружается раньше всех этих скриптов. Декларация задаёт порядок выполнения верхнего уровня файла; тело функции запускается при вызове или переходе. Остальные файлы загружаются при первом обращении к их именованным глобальным функциям, а файл с `main` — перед стартом игры. Поэтому `call(park)` работает и когда `park` объявлена в другом файле. Вызов `init` внутри функции или после другого оператора — ошибка. Каждый файл загружается один раз за запуск игры. Размер Lua/KRL/графа ограничен 8 МБ.

## Переходы и вызовы сцен

`goto(lmao)` переносит выполнение в `function lmao()` без продолжения оставшихся команд текущей функции. KNE преобразует вызов `goto(...)` перед выполнением Lua/KRL; обычный Lua-переход `goto метка` сохраняется. Также доступны `goto_scene(lmao)` и `jump(lmao)`.

`call(lmao)` запускает функцию с возвратом к команде после вызова и сохранением локальных переменных вызывающей функции. Также доступен `call_scene(lmao)`. `return` передаёт результаты обратно; можно передавать несколько аргументов и результатов, включая `nil`. Цель можно передать функцией или строкой с её именем: `call(park)` / `call("park")`. Имена учитывают регистр; пути к файлам в переходах больше не принимаются.

```lua
-- game/scenes/main.krl
function main()
    d(nil, "Начало")
    local answer = call(park, "Алиса")
    d(nil, "Выбран ответ: " .. answer)
    goto(finale)
end
```

```lua
-- game/scenes/park.krl
function park(name)
    d(name, "Мы в парке")
    return choice("Остаться?", {"Да", "Нет"})
end
```

Другим веткам задавайте собственные имена: `function park(...)`, `function finale(...)` или соответствующее имя функции графа. Глобальное объявление `park = function(...) ... end` тоже поддерживается. Общие переменные живут в `state` или глобальной области, локальные — в своей функции. Модули с анонимным `return function` можно использовать через обычный Lua `require`; они не становятся точкой старта игры.

Можно зарегистрировать сцены по имени в скрипте инициализации и вызывать их через тот же API:

```lua
init(-10)
scene("встреча", function(name)
    d(name, "Привет!")
    return 1
end)
-- В игровой сцене: local result = call_scene("встреча", "Алиса")
```

Имена уникальны и сравниваются с учётом регистра. Игровые переходы доступны только внутри игровой сцены. Если вызванная сцена делает `goto_scene`, её собственное продолжение отбрасывается, а предшествующий вызывающий кадр сохраняется: новая сцена по завершении возвращается к нему. Разрешено до 64 активных сцен, включая стартовую, и 10000 переходов между репликами/выборами. Сохранение внутри вложенной сцены восстанавливает выборы, локальные переменные и позицию возврата посредством повторного выполнения истории; изменение сценариев делает старое сохранение несовместимым.

При переносе проекта из предыдущей версии оставьте одну `main`, переименуйте остальные функции и замените переходы по путям на имена функций. У старых графов без поля `FunctionName` остаётся имя `main`, поэтому вспомогательным графам задайте другое имя в редакторе. После перехода на новую модель создайте новые сохранения: прежние слоты не совместимы. Сохранения предпросмотра различают запускаемую функцию и не загружаются как обычная игра.

## Изображения и звук

Все пути API ресурсов отсчитываются от корня проекта. Выход за его пределы запрещён; файл должен существовать.

```lua
function main()
    background("game/backgrounds/park.png")
    show_character("game/characters/alice.png", "left")
    play_music("game/audio/theme.mp3", true)
    d("Алиса", "Привет!")
    play_sound("game/audio/click.wav")
    hide_character()
    background(nil)
    stop_music()
    d(nil, "Конец сцены.")
end
```

Одновременно отображаются один фон и один персонаж. Позиции персонажа: left, center, right (по умолчанию center). Поддерживаются PNG, JPG/JPEG, BMP и GIF; анимация GIF не воспроизводится. Фон заполняет сцену, персонаж сохраняет пропорции.

Музыка и звуковые эффекты используют независимые WPF MediaPlayer. Повтор музыки задаётся вторым параметром play_music(path, loop), по умолчанию true. Форматы: WAV, MP3, WMA, M4A; фактическое воспроизведение зависит от кодеков Windows. Ошибки открытия ресурсов выводятся в журнал.

Также доступны print(...), print_to_ui(text), set_window_title(title), set_window_size(width, height), set_bg_color(color), project_dir. Размер окна принимается от 320×240 до 7680×4320, при этом интерфейс имеет минимальный размер 640×480. Цвет — имя WPF или #RRGGBB / #AARRGGBB.

Для require добавлены папка init_script и корень проекта. Стандартные относительные операции Lua io/os зависят от рабочей папки процесса — папки исполняемого файла движка; для них используйте project_dir.

## Ввод ответа игрока

Блок «Ввод текста» находится в «Нарративе». Задайте переменную ответа, приглашение, заполнитель и длину от 1 до 256 символов (по умолчанию 32, с учётом составных Unicode-символов). Имя переменной — идентификатор Lua из латинских букв, цифр и `_`, без цифры в начале и ключевых слов. Ответ сохраняется строкой в `state`, например `state.playername`; кавычки и любой другой разрешённый настройками текст не исполняются как код.

Проверка: без проверки, точное совпадение или регулярное выражение для всей строки. Для сравнения можно игнорировать регистр. Некорректный шаблон обнаруживается до запуска, вычисление регулярного выражения ограничено по времени. Неудачный ответ показывает заданное сообщение и оставляет ввод открытым; если включено ветвление и выход «Ошибка», выполнение переходит туда. Успешный ответ сохраняется и продолжает «Далее» / «Успех». Отмена доступна кнопкой или Esc только при включённом выходе «Отмена» и не меняет переменную. Ошибочный ответ тоже не перезаписывает прежнее значение.

Автофокус по умолчанию включён. Форматная маска использует `0` для цифры, `L` для латинской буквы, `A` для латинской буквы или цифры и `&` для любого символа; остальные знаки обозначают обязательные разделители, обратная косая черта экранирует следующий знак. Например, `000-000` принимает `123-456`. Отдельная настройка «Скрывать ответ» заменяет отображаемые символы на `•`; она совместима с форматной маской. Проверки и ветки работают одинаково в игре и при тестировании сцены; сохранение восстанавливает ожидающий ввод и принятые ответы.

В коде аналог блока — `text_input(json)`, возвращающий `"success"`, `"error"` или `"cancel"`:

```lua
function main()
    local result = text_input([[{"variable":"playername","prompt":"Как вас зовут?","maximum_length":32}]])
    d(nil, "Привет, " .. state.playername)
end
```

## Сохранения

«Сохранить» записывает ручной слот, «Загрузить» открывает его. После успешной реплики, выбора или команды создаётся автосохранение; для него есть отдельная кнопка. Первый запуск новой сессии сохраняет начальное состояние только при отсутствии прежнего автосохранения. Последующее продолжение новой игры заменяет автосохранение.

Слоты лежат в `<проект>/saves/quick.json`, `auto.json` и `<имя ручного слота>.json`. Экран «Сохранения» открывается из главного меню и паузы: ввод имени и «Записать слот» создаёт или заменяет ручной слот, выбор карточки позволяет загрузить или удалить его. Повреждённые файлы отмечаются и не доступны для загрузки. Имя слота — до 80 символов без пути и точек; preferences/settings зарезервированы. Запись атомарная, максимальный размер — 8 МБ, максимальная история — 10 000 действий.

При первом открытии игры прежние quick/auto из `%LOCALAPPDATA%/KNE/saves/<идентификатор проекта>` копируются в проект, если там ещё нет соответствующего слота. Старые файлы не удаляются и новые не перезаписываются. Слоты предпросмотра импортируются отдельно в `saves/preview/<идентификатор сцены>`. Папка saves исключена из списка исходников и уведомлений редактора.

Переменные игры храните в state. Корень — таблица со строковыми ключами. Разрешены строки, конечные числа, логические значения, вложенные объекты и массивы с последовательными индексами с 1, глубиной до 16 уровней и до 10 000 элементов. Функции, userdata, смешанные таблицы, массивы с пропусками и циклические ссылки не сохраняются.

Позиция сцены и её локальные переменные восстанавливаются повторным выполнением записанной истории с тем же начальным seed генератора случайных чисел. Затем восстанавливается таблица state. Во время повтора журнал подавляется, фон, персонаж и выбранная музыка восстанавливаются; звуковой эффект не повторяется, музыка начинается заново.

Поэтому сценарии для сохранений должны воспроизводиться детерминированно: не используйте внешнее время, произвольный новый seed или изменяющиеся внешние данные для выбора ветвей. Файловые, сетевые и другие побочные эффекты Lua при восстановлении могут выполниться повторно. Произвольные нативные объекты и текущее состояние звукового воспроизведения не сериализуются.

Сохранения привязаны к пути проекта, выбранной сцене и содержимому project.json, Lua/KRL/.knegraph/.cs-файлов. После переноса проекта или изменения сценариев старое сохранение отклоняется. Неудачная загрузка сохраняет текущую игровую сессию.

## Выполнение и остановка Lua

На экране ошибки рядом с «Выход» доступны «Перезапуск», «Вернуться», «Сохранить отчёт в Markdown» и «Консоль». Перезапуск начинает игру с `main` в том же окне и открывает консоль. Она показывает журнал и обновляемые глобальные переменные, `state`, локальные переменные и замыкания активных игровых функций, включая состояние в момент ошибки. Обновления приходят во время выполнения Lua и после каждого успешного шага. Циклические ссылки отмечаются; большие значения ограничены 500 элементами, глубиной 5, 100 элементами на таблицу и 4096 символами на строку, чтобы инспектор сохранял отзывчивость.

«Вернуться» доступна при ошибке перехода `call`/`goto` или возврата из вызванной функции, если есть восстановимый успешный сегмент. Она восстанавливает его посредством повтора истории, включая переменные и позицию вызывающей функции. Ошибочное состояние не сохраняется. Если сценарии изменились или прежний сегмент нельзя сохранить, используйте перезапуск. «Сохранить отчёт в Markdown» копирует только текст раздела «Подробности» в буфер обмена с безопасным Markdown-ограждением; файл на диск не создаётся. «Консоль» открывает и закрывает панель даже на экране ошибки.

Каждое окно игры запускает отдельный скрытый процесс KNE.exe в режиме --lua-worker. Интерфейс общается с ним через JSON по стандартным потокам. Состояние Lua не разделяется между окнами.

«Остановить» в панели F3 и таймаут (по умолчанию 30 секунд, настраивается в `engine/game.json`) завершают рабочий процесс вместе с его дочерними процессами. Это прерывает и цикл с отключённым debug hook. Следующее действие запускает новый процесс и восстанавливает последнюю успешно завершённую операцию. Если state нельзя сохранить, автоматическое восстановление недоступно: закройте окно игры и запустите проект заново.

Закрытие окна игры завершает его процесс. При закрытии родительского канала worker выходит даже во время зависшего сценария.

Журнал сохраняет последние 1000 сообщений и 200 000 символов; сообщение ограничено 4096 символами. Интерфейс обрабатывает максимум 100 сообщений за один тик, чтобы поток вывода не блокировал управление. Размер сообщения протокола также ограничен.

Отдельный процесс обеспечивает остановку и изоляцию сбоев, но не является песочницей безопасности. Lua по-прежнему имеет доступ к стандартной библиотеке и интеграции .NET с правами текущего пользователя. Запускайте доверенные проекты.

## Графика и параметры производительности

«Настройки → Рендер», под группой «Проекты», сохраняет API, VSync, лимит 30/60/144 FPS либо отсутствие лимита, MSAA 0/2/4 и лимит кэша для редактора. Все группы настроек помещаются без прокрутки; при уменьшении окна содержимое масштабируется. «Параметры проекта» слева от «Оформление» задают независимые параметры игры в `engine/performance.json`. В новых проектах файл создаётся автоматически; отсутствие новых файлов в старом проекте сохраняет значения по умолчанию.

OpenGL и Vulkan подключены через Veldrid и готовят неподвижные атласы акварельного логотипа, частиц и периодический рисунок игрового фона. Движение готовых изображений выполняет композитор WPF: на каждом кадре больше нет ожидания GPU, считывания полного окна в CPU и обратной загрузки в WPF. Атлас перестраивается при изменении рисунка, плотности пикселей, API, MSAA или лимита кэша; движение объектов его не перестраивает. Один фоновый поток и нативный контекст обслуживают все слои окна. После подготовки освобождаются нативные текстуры, staging/render targets, а скрытие, сворачивание или закрытие окна освобождает последний контекст и поток. При возвращении графика подготавливается заново. Акварельное искусство создаётся на фоновых STA-потоках; системное уменьшение движения сохраняется.

Автоматический режим сначала пробует OpenGL, затем Vulkan при невозможности создать OpenGL-контекст. Он больше не запускает дорогое сравнение двух API при каждом открытии слоя. Это политика совместимости для подготовки графики, а не обещание самого быстрого API на каждом компьютере. Принудительный режим использует строго выбранный API: OpenGL не заменяется Vulkan. Если драйвер, MSAA или размер подготовки недоступен, используется WPF с причиной в диагностике. Сохранение параметров проекта/сцены применяет графическую политику к уже открытым играм этого проекта. VSync синхронизирует часы анимации с WPF composition, а отключение переключает их на ограниченный таймер. Ограничитель сохраняет дробный остаток времени: небольшой джиттер больше не превращает 60 обновлений в примерно 30. WPF-контролы продолжают использовать системный композитор; выбор API не заменяет его.

Параметры проекта также управляют статистикой в выбранном углу, уведомлением загрузки, консолью отладки, предзагрузкой и папкой сохранений. FPS показывает частоту событий компоновки с учётом лимита, а не количество редких подготовок атласа; это не аппаратный счётчик презентации кадров. Draw Calls и ресурсы KNE относятся к последней нативной подготовке; после освобождения временных ресурсов их объём равен нулю. RAM — рабочий набор процесса интерфейса. Общая VRAM и внутренние Draw Calls WPF недоступны и отмечаются как «н/д». Время логики — последняя операция Lua worker, без последующего checkpoint и передачи по каналу. Debug Mode открывает консоль при запуске; её можно закрыть крестиком и открыть снова через F3 или кнопку на экране ошибки. Она не открывается принудительно на каждом кадре. Скрытая консоль не форматирует переменные, неизменившийся снимок не сериализуется повторно; статистика форматируется не чаще раза в секунду.

«Параметры сцены» предлагает выбрать `.knegraph` или традиционный `.krl` и сохраняет независимые значения в `engine/scene-performance.json`. Высокое качество использует 100 сегментов на ширину видимой волны, среднее — 60, низкое — 30 и статические эффекты. Подготовленный рисунок волн имеет запас полпериода за краем окна для бесшовного движения. Отключение постобработки убирает вспышки и тряску, не меняя сценарий. Политика действует в игре и предпросмотре. После запуска сцены окно показывает время логики, Draw Calls подготовки и отдельное количество объектов; более 100 объектов сопровождаются подсказкой об оптимизации. История замеров ограничена 512 сценами.

«Ограничить кэш ресурсов» доступно в «Рендере» KNE и в параметрах проекта: 16/32/64/128/256/512 МиБ, по умолчанию включено 64 МиБ. Лимит ограничивает необязательный кэш декодированных изображений и бюджет нативной подготовки. Он не является ограничением всей RAM/VRAM: текущие изображения на экране, базовое искусство, среда .NET/WPF и драйвер учитываются отдельно. Фоны, спрайты и текстуры настраиваемого игрового UI используют один кэш на окно, максимум 32 последних использованных ресурса; при включении или уменьшении лимита старые записи сразу вытесняются. Изображение больше лимита можно показать, но оно не удерживается для повторного использования. Отключение убирает ограничение по байтам, сохраняя защиту по количеству записей. Закрытие игры/предпросмотра очищает кэш, отменённая предзагрузка не возвращает в него ресурсы.

Предзагрузка читает текущую и до трёх непосредственно вызываемых сцен, декодирует до 24 изображений в фоне и не выполняет сценарий. Изменение размера файла или времени записи обновляет изображение. Поддерживаются пути блоков и простые строковые литералы `background`/`show_character` в Lua/KRL. Динамические выражения, длинные и экранированные строки загружаются при выполнении. Повреждённые необязательные ресурсы не прерывают предзагрузку.

`saves_path` может быть относительным к проекту или абсолютным. Смена папки не переносит старые сохранения. Выбранная папка исключается из дерева файлов и наблюдения за изменениями. Красная кнопка сброса с подтверждением удаляет только распознанные сохранения этого проекта из сохранённого пути: настройки, чужие, повреждённые и вложенные файлы остаются. После сброса старые quick/auto из профиля не импортируются повторно.

GPU-проверки требуют Windows и работающие драйверы. `KNE_GPU_TEST=1` включает реальные тесты обоих API, MSAA, живого WPF→GPU пути и очистки контекстов; без переменной они явно пропускаются. `KNE_GPU_PROBE=<папка>` дополнительно сохраняет JSON с наблюдениями времени открытия, готовности слоёв и задержек диспетчера. Это диагностические измерения отдельного WPF-окна, не обещание общего FPS или сравнение с прошлой версией.

Окно «Параметры проекта» сохраняет размер 780×840: название сверху, графика и производительность в двух колонках, ниже диагностика и путь сохранений. «Переименовать» меняет отображаемое название в `project.json` после «Сохранить»; папка и ссылки на файлы остаются прежними. «Отмена» отбрасывает изменения.

`graphics.texture_quality` задаёт «Оригинал», «Половина» или «Четверть»: размеры декодированных фонов, персонажей и текстур экранов/UI уменьшаются по каждой оси, исходные файлы остаются прежними. Смена качества обновляет открытую игру без перезапуска сценария и музыки. В этом окне кэш выбирается из 64/128/256/512 МБ; загруженные старые лимиты 16/32 МиБ сохраняются отдельным пунктом. `unload_previous_scene` очищает необязательные ресурсы при переходе в другой файл сцены, сохраняя текущие изображения и текстуры интерфейса. По умолчанию выключено.

`max_async_tasks` — 32, 64 или 128 одновременно активных задач Lua, включая основную ветку; по умолчанию 128. Применяется при следующем запуске сценария, ограничение 64 веток в одной группе сохраняется. `audio_buffer` — `low_latency`, `balanced` (по умолчанию) или `stable`: два выходных буфера по 25, 75 или 150 мс. Профиль применяется при следующем открытии аудиофайла; фактическая задержка зависит от устройства. Аудио использует NAudio WinMM/WASAPI и установленные кодеки Windows Media Foundation.

Внизу свёрнута **Danger Zone**. Сброс сохранений требует подтверждения. «Удалить проект» требует отдельного подтверждения и ещё 72 нажатий; под кнопкой виден остаток. Сворачивание раздела или отмена сбрасывает счётчик. По завершении закрываются игры и предпросмотры этого проекта, удаляется проверенная папка проекта и запись в истории, открывается главный экран. Внешняя папка сохранений остаётся на диске; ссылки и junction внутри удаляемого проекта отклоняются до удаления файлов.

## Шейдерные блок-схемы

В «Новая блок-схема» выберите `.knegraph` для сценария или `.kneshader` для шейдера. Новые проекты содержат `game/shaders`; новые шейдеры, выбранные в корне проекта, сохраняются туда. Шейдерные файлы открываются во вкладках редактора, но не объявляют Lua-функции и не участвуют в поиске `main()`. Раздел «Шейдеры» находится между «Конфигурации» и «Плагины»; радужный акцент двигается только при наведении, поэтому открытая библиотека не анимирует все карточки одновременно. В адаптированных цветовых режимах остаются контрастный цвет и отдельный значок. В игровую схему разрешён «Контейнер GLSL/HLSL»; остальные операции шейдеров требуют `.kneshader`.

Минимальная схема создаётся как **Texture → Fragment Output**. Это граф значений: входы слева имеют имена, выходы справа можно разветвлять. Вход подключается к одному выходу; повторное подключение заменяет его источник. ПКМ по входу отсоединяет его, по выходу — все его потребители. Копирование, вставка, дублирование, выделение, изменение размеров и отмена работают как в игровой схеме. Циклы значений запрещены; незавершённый документ можно сохранять, а компиляция требует ровно один Fragment Output.

Доступны 47 операций: контейнер GLSL/HLSL; Texture, UV, Time, Screen Position; Exposed Float/Vector/Color; Tiling & Offset, Rotate, Polar Coordinates, Flipbook, Twirl; Simplex Noise, Voronoi, Checkerboard, линейный и радиальный Gradient; Split/Combine RGBA; Hue Shift, Saturation, Contrast, Brightness, Invert, Grayscale, Posterize; Gaussian/Box Blur, Motion Blur, Bloom/Glow, Chromatic Aberration, Vignette, Scanlines, Lens Distortion, Pixelate, Sharpen, Sobel, Dithering; Mix, Add, Subtract, Multiply, Screen, Step, Smoothstep и Fragment Output. Макроэффекты обрабатывают результат подключённого графа, включая выборки соседних пикселей. Параметры и значения по умолчанию каждого блока есть в HTML-справке «Помощь».

Texture задаёт цель файла: всю игровую сцену, слой фона, спрайт, игровой UI или экран с указанным названием. Несколько Texture одного файла должны иметь одну цель. Файлы сами не запускаются: подключите контейнер в игровую цепочку, и эффект включится, когда выполнение дойдёт до него. В коде это `apply_shader("game/shaders/effect.kneshader")`; `apply_shader(путь, false)` отключает эффект. В свойствах игрового контейнера есть такая же галочка. Несколько активных файлов одной цели выполняются в порядке вызовов; повторный вызов переносит эффект в конец цепочки. Состояние восстанавливается при загрузке сохранения и сбрасывается при перезапуске игры.

В том же разделе библиотеки есть игровые команды **«Удалить шейдер с слоя»** и **«Удалить все шейдеры»**. Первая удаляет все активные эффекты выбранной цели Texture: сцена, фон, спрайт, UI или экран по названию (без учёта регистра). Вторая очищает все эффекты. Файлы `.kneshader` остаются в проекте. В коде доступны `clear_layer_shaders("background", "", false)` и `clear_shaders(false)`.

У обеих команд есть галочка **«Не отображать шейдеры после этого блока, пока поток не дойдёт до следующего контейнера GLSL/HLSL»** (последний аргумент API — `true`). Пока она действует, остальные и вновь включаемые эффекты тоже скрыты. Следующий контейнер этого же потока снимает его блокировку. `call` и `goto` сохраняют поток; параллельная ветка не снимает чужую блокировку. Если их несколько, возобновиться должен каждый владелец. Завершение потока без нового контейнера оставляет блокировку до перезапуска игры. Сохранение и восстановление воспроизводят это состояние.

Двойной клик по контейнеру открывает или создаёт его `.kneshader`. Внутри шейдерного файла контейнер остаётся чистой функцией от UV и текстуры родителя, его собственная цель не переопределяет родительскую. Все блоки «Плагины» доступны в обоих форматах: внутри шейдера они выполняются как команды подготовки при его вызове. Выходы этих команд соединяются только с другими плагинами; независимые цепочки начинаются в порядке хранения блоков. `Подключить .lua/.cs` сохраняет правило однократного подключения, «Скрипт» запускается при каждом вызове. Плагинные команды вложенных контейнеров также входят в подготовку. В отдельном графическом предпросмотре плагины не исполняются. Time передаётся как время в секундах, Screen Position учитывает положение окна на мониторе. Экран выбирается по названию без учёта регистра.

«Предпросмотр шейдера» открывает отдельное окно с тестовой или выбранной текстурой. Exposed Float/Vector/Color доступны там как слайдеры и палитра; изменения предпросмотра не переписывают файл. Значения для игры задаются в свойствах блоков. Режим «Код» показывает GLSL, экспорт сохраняет `.frag` или `.hlsl`. Генерация использует GLSL → SPIR-V → GLSL/HLSL через [Veldrid.SPIRV](https://github.com/veldrid/veldrid-spirv); реальное выполнение использует выбранный OpenGL или Vulkan. В принудительном режиме другой API не подставляется. Ошибки шейдеров доступны в анализе проекта и при запуске.

В «Параметрах сцены» галочка **«Не отображать шейдеры»** сохраняется как `hide_shaders` отдельно для `.krl` и `.knegraph`, по умолчанию выключена. Она убирает эффекты и восстанавливает исходные элементы, сохраняя их обработку ввода. В игре изменение применяется к открытым окнам; предпросмотр сцены читает параметры при открытии. Файлы шейдеров читаются при вызове контейнера, а в отдельном предпросмотре шейдера — при его открытии; после правки активного графа перезапустите соответствующее окно.

Шейдерная обработка WPF выполняется через ограниченный захват и обратное чтение GPU: до 30 обновлений в секунду, не выше выбранного лимита FPS, максимум 2048 пикселей по большей стороне с учётом качества текстур и бюджета кэша. Это отдельный предел эффектов, а не общий FPS игры. Статический кадр сохраняется до изменения сцены; анимация шейдера повторно использует исходный снимок, если сама сцена неподвижна. Цепочка эффектов передаёт промежуточные текстуры внутри GPU и читает только конечный кадр. Полноэкранные проходы не используют лишний MSAA. Повторно используются поверхности, загружаемая текстура и до 17 вариантов программ с пайплайнами. Все графические слои и шейдеры одного окна делят один native-контекст; его память зависит и от драйвера. Пустая схема Texture → Fragment Output не создаёт GPU-ресурсов. После отключения эффектов промежуточные ресурсы освобождаются; последний владелец окна освобождает контекст.

Одновременно доступны до 16 активных файлов, каждый до 2 МБ; до 500 узлов с контейнерами, 12 уровней вложенности и 512 консервативно оценённых выборок текстуры на пиксель. Сложные цепочки размытия отклоняются. Невызванные файлы не читаются игрой; их ошибки можно найти через «Анализ проекта». Файлы внутри `plugins` отключены безопасным режимом, а команды внешних плагинов пропускаются с записью в консоль.

## Проверки

tests/KNE.Tests содержит проверки путей, конфигурации, файловых операций, настроек, дерева/поиска, наблюдения за файлами, редактора кода/графов, компиляции блоков, визуального оформления экранов, диалогов, ресурсов, именованных сохранений и отдельного процесса Lua. Интеграционные проверки проверяют отмену цикла без hook, таймаут, os.exit, восстановление и закрытие канала.

Проверки файловой системы используют временные каталоги. WPF проверяется на STA-потоке с диспетчером: загрузка сцены, декодирование PNG, выбор ветки, ручные сохранения и компактная раскладка настроек. `KNE_AUDIO_TEST=1` включает проверки настоящего аудиоустройства с нулевой громкостью: WAV, MP3, три размера буфера, завершение воспроизведения и освобождение файлов. Без переменной эти аппаратные проверки явно пропускаются.


## Рендер схемы и удаление блоков

Тени карточек рисуются отдельными фигурами под блоками. Текст, порты и содержимое не проходят через растровый эффект тени и перерисовываются при масштабе 40–150%; включены настройки форматирования текста и округления раскладки WPF. Delete удаляет выделенную группу и её связи одним отменяемым действием. В полях ввода Delete по-прежнему удаляет текст.

## Заблокированные варианты и выбор с таймером

У каждого ответа в блоке «Выбор» можно включить условие блокировки: сравнение переменной state с флагом, числом, строкой или другой переменной. Истинное условие блокирует ответ. Доступность фиксируется при показе выбора, исходные номера и связи ответов сохраняются. Если все варианты заблокированы, игра сообщает ошибку с исходным файлом и блоком.

Виды блокировки: затемнение, зачёркивание, глитч, скрытие букв и циклическое превращение текста в нечитаемые символы и обратно. Пояснение при наведении включается отдельно; его можно разместить поверх варианта либо рядом. Недоступные ответы нельзя активировать мышью, клавиатурой или вызовом API выбора.

«Выбор с таймером» добавляет время больше 0 и до 3600 секунд (по умолчанию 10), номер варианта по умолчанию и вид таймера: полоса вверху экрана или число. При истечении времени runtime выбирает заданный доступный ответ; если тот заблокирован — первый доступный по исходному порядку. Таймер использует часы сцены, останавливается на паузе и восстанавливается из сохранения вместе с оставшимся временем. Обычный `choice()` остаётся совместимым; расширенный API — `kne_choice(json)` с `prompt`, `options` (`text` и необязательный `lock`) и необязательным `timer`.

## Диагностика и восстановление движка

Журнал движка хранится в `%LOCALAPPDATA%/KNE/diagnostics`: последние 200 операций, открытый проект, время, сведения об ОС/.NET, процесс и режим плагинов. При необработанной ошибке сохраняется JSON-журнал и текстовый отчёт с первичной причиной, компонентом и стеком. Ошибки сценария продолжают показываться в окне игры; сбои самого приложения открывают отдельное окно восстановления с действиями «Закрыть», «Перезапустить движок», «Перезапустить без плагинов».

Отдельный скрытый наблюдатель ждёт завершения процесса. После аварийного выхода, включая нативный сбой, он открывает сохранённый отчёт в новом процессе. Штатное закрытие не вызывает окно ошибки. Для нативных сбоев показываются код завершения и последние известные операции; точный виновник не приписывается последней операции без доказательств. Если запись отчёта недоступна, окно управляемой ошибки показывает исходную причину и ошибку сохранения.

Запуск `KNE.exe --disable-plugins` отключает `include_lua`, `include_cs`, `run_script`, внешние загрузчики Lua (`require`, `dofile`, `loadfile`, `package.loadlib`) и автоматическую инициализацию файлов из каталогов `plugins`. Проектные main и init вне каталогов плагинов остаются активными. Режим передаётся всем игровым worker-процессам и виден в заголовке редактора; файлы проекта не меняются. Сохранения обычного и отключённого режима различаются. Обычная кнопка перезапуска возвращает запуск с плагинами.

## Plugin API

Расширения на C# и Lua могут добавлять блоки, группы, интерфейсы, темы, игровые экраны, события, обработчики ввода и валидаторы. Контракт, модель прав и рабочие примеры описаны в [документации SDK](docs/plugin-api.md).

В **Настройки → Плагины** можно подключить `.cs`/`.lua` ко всему KNE без манифеста. После сохранения они доступны в редакторе и тестовых запусках всех проектов. Удаление записи отключает плагин и сохраняет исходный файл; для переноса игры зависимости нужно поставлять в самом проекте.
