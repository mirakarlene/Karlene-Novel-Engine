# Karlene Novel Engine

WPF-приложение для создания и запуска визуальных новелл на Lua/KRL. Для сборки требуются Windows и стабильный .NET 10 SDK (10.0.100 или новее в ветке 10.0). `global.json` выбирает последнюю установленную стабильную версию SDK 10.0.

## Сборка и запуск

```powershell
dotnet build KNE.sln
dotnet test KNE.sln
dotnet run --project KNE.csproj
```

Для запуска готовой сборки без SDK требуется .NET Desktop Runtime 10 для Windows соответствующей архитектуры. Приложение и тесты используют `net10.0-windows`.

Публикация для Windows x64 с установленным Desktop Runtime:

```powershell
dotnet publish KNE.csproj -c Release -r win-x64 --self-contained false -o artifacts/publish/win-x64
```

## Работа с проектом

«Создать проект» создаёт готовую папку и сразу открывает её. «Открыть проект» принимает папку с project.json. На главном экране сохраняются восемь последних проектов.

Дерево показывает папки с файлами, таблица — список файлов. Поиск без учёта регистра фильтрует оба представления по имени и относительному пути; допустимы разделители / и \. Внешние изменения подхватываются автоматически после короткой задержки. «Обновить» позволяет перечитать проект вручную; перед запуском конфигурация также перечитывается.

Таблица доступна только для просмотра. Создание, копирование, переименование и удаление выполняются через кнопки и меню действий. Существующие файлы не перезаписываются. Для смены точек входа сначала измените project.json: удаление и переименование активных точек входа и самой конфигурации запрещены. Отсутствующая точка входа не мешает работе с обычными файлами. Символические ссылки и junctions не поддерживаются.

Настройки редактора и последние проекты сохраняются в %LOCALAPPDATA%\KNE\settings.json. Пустой путь к редактору означает Блокнот. Старый EditorPath из KNE.dll.config читается при первом запуске.

## Код и блок-схемы

Выберите `.lua`, `.krl` или `.knegraph` в дереве/таблице и нажмите «Открыть сценарий», дважды щёлкните по файлу или выберите действие «Редактировать». Lua/KRL открываются во встроенном текстовом редакторе. Действие «Внешний редактор» использует редактор из настроек.

«Новая блок-схема» создаёт отдельный `.knegraph` внутри проекта с готовой цепочкой «Начало → Реплика → Конец». Переключатель «Код / Блок-схема» находится справа внизу области редактирования. Для графа «Код» показывает сгенерированный Lua только для чтения; «Копия как KRL…» создаёт новый файл для ручного редактирования. Произвольный Lua/KRL обратно в блоки не преобразуется.

Добавляйте блоки из палитры, перетаскивайте их за заголовки. Для соединения нажмите выход блока, затем вход другого; правая кнопка по выходу удаляет связь, Esc отменяет соединение. Свойства выбранного блока редактируются справа и применяются кнопкой «Применить свойства», при сохранении или смене выбранного блока. Варианты выбора задаются по одному на строку; порядок строк соответствует порядку выходов. При изменении текста вариантов связи сохраняются по их позиции. Масштаб меняется ползунком или Ctrl+колесом; полосы прокрутки перемещают полотно.

Доступны начало, реплика, выбор, условие, переменная, фон, персонаж, скрытие персонажа, музыка, остановка музыки, звук и конец. Переменные хранятся в `state`: укажите имя, тип (число, строка, логическое) и значение. Для чисел используйте точку, для логических значений — `true`/`false`. Условия поддерживают равенство/неравенство и числовые сравнения. Пустой путь блока «Фон» убирает фон. Пути ресурсов задаются от корня проекта; файл можно выбрать кнопкой.

«Сохранить» или Ctrl+S сохраняет сценарий. Незавершённый граф разрешено сохранить как черновик. Перед предпросмотром кода, экспортом и запуском проверяются связи: ровно одно начало, все выходы подключены, все блоки достижимы, циклы отсутствуют. Первая версия поддерживает до 500 блоков и до 20 ответов в одном выборе. «Отменить»/«Повторить» возвращают изменения графа; Ctrl+Z/Ctrl+Y работают на полотне, а в текстовых полях отменяют ввод.

«Запустить сцену» сохраняет и запускает открытый файл независимо от текущей главной сцены. Его сохранения лежат отдельно в подпапке `preview/<идентификатор сцены>` каталога сохранений проекта. «Сделать главной» сохраняет сценарий и обновляет `entry_points.main_scene` в `project.json`; после этого «Запустить проект» использует эту сцену. Визуальная сцена преобразуется в Lua в памяти отдельного worker-процесса и использует тот же API, диалоги, выборы и восстановление истории, что и ручной код.

При переключении сценария, закрытии редактора, выходе из проекта или приложения предлагается сохранить несохранённые изменения. Внешние правки не перезаписываются: при конфликте сохранение сообщает ошибку. Для графа можно экспортировать KRL-копию; для ручного кода скопируйте текст, затем закройте редактор с отказом от сохранения и откройте файл заново. Открытый сценарий нужно закрыть перед переименованием или удалением.

## Оформление и настройки игры: engine

Новый проект содержит готовые `engine/window.json`, `theme.json`, `game.json`, `state.json` и `engine/README.txt`. Это редактируемые настройки конкретной игры; изменения применяются при следующем запуске окна игры. Настройки движка не записываются в сохранения игрока.

По умолчанию окно имеет размер 1280×720, открывается по центру экрана и показывает главное меню «Начать игру / Продолжить / Выйти». Сцена занимает всё окно: фиолетовый фон с векторным узором, персонаж и диалог поверх фона. Журнал и командная строка скрыты до F3. Escape открывает меню паузы, F11 переключает полноэкранный режим. «Продолжить» загружает автосохранение, а при его отсутствии — ручной слот. Кнопки загрузки в сцене позволяют выбрать слот явно. Новая игра из меню паузы требует подтверждения; последнее сохранение остаётся доступным.

- `window.json`: `width`, `height`, `position` (`center` / `manual`), `left`, `top`, `mode` (`windowed` / `maximized` / `fullscreen`) и `resizable`. Координаты и размеры задаются в логических пикселях Windows (DIP); начальная ручная позиция ограничивается виртуальным экраном.
- `theme.json`: `font_family`, `background_color`, `pattern`, `pattern_color`, `background_image`, `accent_color`, `text_color`, `button_color`, `character_width` и секции `dialogue`, `menu`. В диалоге настраиваются `height`, `margin`, `padding`, `corner_radius`, `font_size`, `speaker_font_size`, `background_color`, `border_color`, `text_color`, `speaker_color`. В меню: `width` (240–560), `title_font_size`, `subtitle_font_size`, `alignment` (`left` / `center` / `right`), `overlay_color`.
- `game.json`: `main_menu`, `subtitle`, `start_label`, `continue_label`, `exit_label`, `auto_save`, `debug_enabled`, `execution_timeout_seconds` (1–3600). `main_menu: false` запускает сцену сразу; меню паузы остаётся доступным. `debug_enabled: false` отключает открытие отладки по F3.
- `state.json`: начальные переменные таблицы `state`: строки, конечные числа, логические значения и вложенные объекты до 16 уровней. Они загружаются до `gamelogic.lua`, который может переопределить значения. Массивы и `null` не поддерживаются.

Например, замените окно диалога и стандартный фон в `engine/theme.json` (неуказанные поля сохраняют значения по умолчанию):

```json
{
  "background_image": "game/backgrounds/title.png",
  "pattern": false,
  "dialogue": {
    "height": 220,
    "font_size": 26,
    "background_color": "#E6201630",
    "speaker_color": "#FFFFCC88"
  }
}
```

Пути изображений задаются от корня проекта. Поддерживаются PNG, JPG/JPEG, BMP и GIF; фон масштабируется с заполнением окна. `background(...)` перекрывает стандартный фон, `background(nil)` возвращает его. `set_bg_color(...)` заменяет узор и стандартное изображение сплошным цветом; возврат к цвету `background_color` восстанавливает оформление. Lua-команды размера и заголовка окна имеют приоритет над начальными настройками.

Некорректные настройки сообщаются с ошибкой до запуска игры. Отдельные отсутствующие файлы используют значения по умолчанию; проекты без всех четырёх JSON-файлов сохраняют прежний запуск сцены без меню и размер 800×600. Чтобы включить новое оформление в старом проекте, добавьте нужные JSON-файлы в `engine`; пустого `{}` достаточно для стандартных параметров. Изменение темы, окна или меню не отменяет совместимость сохранений; изменение `state.json` — отменяет.

«Запустить сцену» в редакторе использует то же оформление и пропускает начальное главное меню; сохранения предпросмотра остаются отдельными.

## project.json

```json
{
  "metadata": { "name": "Моя новелла", "version": "1.0.0" },
  "game_info": { "title": "Моя новелла" },
  "entry_points": {
    "main_scene": "game/scenes/main.krl",
    "init_script": "game/scripts/gamelogic.lua"
  }
}
```

Пути задаются относительно корня проекта. Поддерживается старое поле name в корне JSON. Для старого шаблона, где указан game/scripts/game_init.lua, используется game/scripts/gamelogic.lua, если первый файл отсутствует. Ошибки JSON и отсутствующие явно заданные точки входа сообщаются пользователю.

## Диалоги и выборы

KRL использует синтаксис Lua. Сначала выполняется init_script, затем main_scene, затем функция main() из сцены. Отдельный main.lua не требуется.

```lua
-- game/scripts/gamelogic.lua
state.score = 0
function process_command(command)
    print("Команда:", command)
end
```

```lua
-- game/scenes/main.krl
function main()
    d(nil, "Добро пожаловать!")
    d("Алиса", "Куда пойдём?")
    local answer = choice("Выберите маршрут", {"Домой", "В парк"})
    state.score = answer
    if answer == 2 then
        d("Алиса", "Идём в парк.")
    else
        d("Алиса", "Возвращаемся домой.")
    end
    d(nil, "Очки: " .. state.score)
end
```

d(speaker, text) приостанавливает main() на реплике. Кнопка «Далее», пробел или щелчок по тексту продолжают сцену. choice(prompt, options) показывает от 1 до 20 непустых вариантов и возвращает индекс выбранного ответа, начиная с 1. Реплики и выборы работают внутри main() и вызываемых ею функций; d() вне корутины сцены пишет сообщение в журнал.

Для отладки доступна строка команд: Enter вызывает process_command(command), если такой обработчик объявлен. Команды выполняются последовательно.

## Изображения и звук

Все пути API ресурсов отсчитываются от корня проекта. Выход за его пределы запрещён; файл должен существовать.

```lua
function main()
    background("game/backgrounds/park.png")
    show_character("game/characters/alice.png", "left")
    play_music("game/audio/theme.mp3", true)
    d("Алиса", "Привет!")
    play_sound("game/audio/click.wav")
    hide_character()
    background(nil)
    stop_music()
    d(nil, "Конец сцены.")
end
```

Одновременно отображаются один фон и один персонаж. Позиции персонажа: left, center, right (по умолчанию center). Поддерживаются PNG, JPG/JPEG, BMP и GIF; анимация GIF не воспроизводится. Фон заполняет сцену, персонаж сохраняет пропорции.

Музыка и звуковые эффекты используют независимые WPF MediaPlayer. Повтор музыки задаётся вторым параметром play_music(path, loop), по умолчанию true. Форматы: WAV, MP3, WMA, M4A; фактическое воспроизведение зависит от кодеков Windows. Ошибки открытия ресурсов выводятся в журнал.

Также доступны print(...), print_to_ui(text), set_window_title(title), set_window_size(width, height), set_bg_color(color), project_dir. Размер окна принимается от 320×240 до 7680×4320, при этом интерфейс имеет минимальный размер 640×480. Цвет — имя WPF или #RRGGBB / #AARRGGBB.

Для require добавлены папка init_script и корень проекта. Стандартные относительные операции Lua io/os зависят от рабочей папки процесса — папки исполняемого файла движка; для них используйте project_dir.

## Сохранения

«Сохранить» записывает ручной слот, «Загрузить» открывает его. После успешной реплики, выбора или команды создаётся автосохранение; для него есть отдельная кнопка. Первый запуск новой сессии сохраняет начальное состояние только при отсутствии прежнего автосохранения. Последующее продолжение новой игры заменяет автосохранение.

Слоты лежат в %LOCALAPPDATA%\KNE\saves\<идентификатор проекта>\quick.json и auto.json. Запись атомарная, максимальный размер — 8 МБ, максимальная история — 10 000 действий.

Переменные игры храните в state. Разрешены строки, конечные числа, логические значения и вложенные таблицы со строковыми ключами, глубиной до 16 уровней. Функции, userdata, числовые ключи и циклические ссылки не сохраняются.

Позиция сцены и её локальные переменные восстанавливаются повторным выполнением записанной истории с тем же начальным seed генератора случайных чисел. Затем восстанавливается таблица state. Во время повтора журнал подавляется, фон, персонаж и выбранная музыка восстанавливаются; звуковой эффект не повторяется, музыка начинается заново.

Поэтому сценарии для сохранений должны воспроизводиться детерминированно: не используйте внешнее время, произвольный новый seed или изменяющиеся внешние данные для выбора ветвей. Файловые, сетевые и другие побочные эффекты Lua при восстановлении могут выполниться повторно. Произвольные нативные объекты и текущее состояние звукового воспроизведения не сериализуются.

Сохранения привязаны к пути проекта, выбранной сцене и содержимому project.json, Lua/KRL/.knegraph-файлов. После переноса проекта или изменения сценариев старое сохранение отклоняется. Неудачная загрузка сохраняет текущую игровую сессию.

## Выполнение и остановка Lua

Каждое окно игры запускает отдельный скрытый процесс KNE.exe в режиме --lua-worker. Интерфейс общается с ним через JSON по стандартным потокам. Состояние Lua не разделяется между окнами.

«Остановить» в панели F3 и таймаут (по умолчанию 30 секунд, настраивается в `engine/game.json`) завершают рабочий процесс вместе с его дочерними процессами. Это прерывает и цикл с отключённым debug hook. Следующее действие запускает новый процесс и восстанавливает последнюю успешно завершённую операцию. Если state нельзя сохранить, автоматическое восстановление недоступно: закройте окно игры и запустите проект заново.

Закрытие окна игры завершает его процесс. При закрытии родительского канала worker выходит даже во время зависшего сценария.

Журнал сохраняет последние 1000 сообщений и 200 000 символов; сообщение ограничено 4096 символами. Интерфейс обрабатывает максимум 100 сообщений за один тик, чтобы поток вывода не блокировал управление. Размер сообщения протокола также ограничен.

Отдельный процесс обеспечивает остановку и изоляцию сбоев, но не является песочницей безопасности. Lua по-прежнему имеет доступ к стандартной библиотеке и интеграции .NET с правами текущего пользователя. Запускайте доверенные проекты.

## Проверки

tests/KNE.Tests содержит проверки путей, конфигурации, файловых операций, настроек, дерева/поиска, наблюдения за файлами, редактора кода/графов, компиляции блоков, диалогов, ресурсов, сохранений и отдельного процесса Lua. Интеграционные проверки проверяют отмену цикла без hook, таймаут, os.exit, восстановление и закрытие канала.

Проверки файловой системы используют временные каталоги. WPF проверяется на STA-потоке с диспетчером без показа окон: загрузка сцены, декодирование PNG, выбор ветки и загрузка ручного сохранения. Воспроизведение звука на физическом устройстве автоматическими тестами не проверяется.
