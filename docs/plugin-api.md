# KNE Plugin API v1

Расширения — доверенный код с доступом к публичным типам сборки KNE, .NET и ОС. Это не песочница. Их следует устанавливать только из источника, которому доверяет пользователь. API не требует SDK или компилятора на компьютере игрока: исходники C# компилируются Roslyn в памяти, Lua исполняется в NLua.

## Установка и права

Плагины можно подключить ко всему KNE: откройте **Настройки → стрелка → Плагины → Добавить…** и выберите один или несколько `.cs`/`.lua`. Первая страница содержит основные настройки, вторая — список плагинов и сведения о выбранном файле. Стрелки переключают страницы, сохраняя несохранённый список. Манифест для подключения не нужен. Нажмите **Сохранить**: расширения подключатся к редактору и будут доступны в каждом открываемом проекте, предпросмотре и тестовой игре. Список хранится в пользовательском профиле KNE, файлы остаются на исходном месте. **Убрать из списка** отключает файл после сохранения, не удаляя его с диска; уже открытые игровые окна нужно перезапустить. Для переноса игры на другой компьютер поставляйте её зависимости вместе с проектом через манифесты.

На главном экране глобальное расширение получает `Api.IsEditor=true`, `MainWindow.Project=null`, а `ProjectDirectory` указывает на папку настроек KNE. При открытии проекта реестр создаётся заново с корнем проекта; регистрации не должны предполагать, что проект уже выбран. Ошибка загрузки или выполнения плагина, отсутствующий подключённый файл, неподдерживаемый API и конфликт регистраций принудительно открывают штатный экран сбоя KNE с причиной и сведениями о плагине. Это относится также к игровому worker и предпросмотру. Выберите **Перезапустить без плагинов**, чтобы убрать проблемный файл в настройках. Безопасный режим отключает также эти расширения. Один файл, подключённый одновременно глобально и через проектный манифест, выполняется один раз за сессию.

В папке проекта `plugins` разместите исходник и `*.kneplugin.json`:

```json
{"id":"author.extension","source":"plugins/Extension.cs","apiVersion":1}
```

`source` — путь от проекта к `.cs` или `.lua`. Манифесты загружаются по имени файла в стабильном порядке. ID расширений уникальны. Поддерживается до 64 манифестов, манифест до 64 КБ, исходник до 8 МБ. Манифестный Lua-модуль не становится игровой сценой и не участвует в поиске `main()`. Изменение исходников или манифестов изменяет отпечаток сохранений. Для применения изменённого редакторского расширения закройте и снова откройте проект.

### Сведения о плагине

Чтобы заполнить правую панель на второй странице настроек, положите рядом с `Extension.cs` или `Extension.lua` файл `Extension.kneplugin.json`. Старые манифесты и плагины без манифеста поддерживаются; отсутствующие сведения показываются как неуказанные. Язык определяется по расширению исходника. Автор и дата берутся из манифеста, а не из времени создания копии файла.

```json
{
  "id": "author.extension",
  "source": "plugins/Extension.cs",
  "apiVersion": 1,
  "name": "Название расширения",
  "author": "Автор",
  "createdAt": "2026-10-23",
  "readmeFile": "Extension.README.md",
  "license": "MIT"
}
```

`name`, `author`, `createdAt`, `readme`, `readmeFile`, `license`, `licenseFile` необязательны. `createdAt` имеет формат `yyyy-MM-dd`. `readme` и `license` содержат обычный текст; `readmeFile` и `licenseFile` читают UTF-8 документы до 256 КБ относительно папки манифеста и имеют приоритет над встроенным текстом. Выход за эту папку запрещён. Инструкции и лицензия отображаются как доступный для копирования текст, без исполнения HTML, Markdown или кода плагина. Ошибка чтения сведений при выборе файла показывается в правой панели; ошибка при фактическом подключении вызывает экран сбоя.

Обычная загрузка расширений требует пользовательского процесса. Если KNE запущен администратором, расширения не запускаются; приложение предлагает перезапустить KNE без повышения прав. Это исключает незаметное наследование повышенного токена. `PluginPrivileges.RequestAdministrator(executable, arguments, reason)` сначала показывает программу, аргументы и причину, затем запрашивает системный UAC; отказ возвращает `false`. Функция не повышает права основного движка. Доверенный код всё равно может обращаться к ОС напрямую, а Windows требует разрешение на повышение прав. Вызов с диалогом удобнее выполнять из UI-команды: игровой worker ограничен временем выполнения.

Запуск `KNE --disable-plugins` отключает обнаружение расширений, внешние Lua-модули и C#-плагины. Пользовательский блок в этом режиме сообщает, что его расширение недоступно; сохранённые параметры и связи сохраняются в графе.

## Контексты и время жизни

C#-файл содержит один публичный класс `IKnePlugin` с публичным конструктором без параметров. Его `Execute(IPluginContext)` регистрирует возможности через `context.Api`. Прежние `Get`, `Set`, `Log`, `include_cs`, `include_lua` и `run_script` поддерживаются.

Манифест исполняется отдельно в редакторе, в игровом worker и в игровом окне для регистрации WPF-экранов и перехватчиков ввода. `Api.IsEditor`, `Api.IsPlayer` различают эти среды; оба значения `false` в игровом worker. `Api.Engine` содержит соответствующий `MainWindow`, `GameWindow` или `LuaRuntime`; их `Project` даёт доступ к модели проекта. Между этими процессами не разделяются экземпляры классов и статические поля. Общее игровое состояние передавайте через `state` и JSON.

Регистрация не должна начинать игру, воспроизводить звук или менять состояние. Такие операции выполняйте в событиях/блоках. Не захватывайте `IPluginContext` из `Execute` для последующей работы: контекст действителен только в текущем синхронном вызове, на его потоке. Обработчики получают собственный контекст. Отслеживайте `CancellationToken`; зависший worker завершается движком. UI-фабрики и команды вызываются на WPF Dispatcher, должны быстро возвращаться; длительный HTTP или расчёты выполняйте асинхронно.

Регистры и делегаты живут одну сессию проекта. `Api.Own(disposable)` освобождает ресурс при закрытии; ресурсы API, Lua и сборки также освобождаются. Не сохраняйте ссылки на закрытые окна и контексты во внешних статических коллекциях.

## Блоки

`RegisterGroup(BlockGroup)` добавляет группу с ID, названием, цветом и Unicode-иконкой перед последней группой «Плагины». `RegisterBlock(PluginBlock, callback)` размещает блок в любой встроенной или зарегистрированной группе. Входы и выходы — именованные порты потока; входы сходятся в одну операцию блока. Это не типизированные шейдерные data-порты. Callback получает текущий `IPluginContext`, `JsonObject` параметров и возвращает номер выходного порта **от 1**. Блок без выходов возвращает 0 и завершает ветку.

Параметры `PluginParameter`: `text`, `slider`, `choice`, `boolean`. Есть ID, подпись, значение по умолчанию, Minimum/Maximum, Choices. До 32 параметров и 20 портов каждого направления. Ползунок и bool передаются как JSON-число и логическое значение; текст и choice — строки. Диапазоны и варианты проверяются при регистрации и выполнении. В `.knegraph` сохраняются ID блока, параметры, внешний вид и именованные порты, поэтому проект можно открыть без установленного расширения.

`RegisterLuaBlock(definition, functionName)` вызывает именованную Lua-функцию, передаёт параметры JSON-строкой и ожидает такой же номер выхода. Функция должна быть объявлена в Lua-манифесте либо заранее подключённом Lua-модуле.

`BeforeExecute("Dialogue", hook)` позволяет заменить `PluginExecution.Text` и `Speaker` до показа. Для остальных типов используйте имя `ScriptNodeKind` (`SetVariable`, `Background` и т. п.) или `"*"`; hook получает ID блока и контекст. Для реплик hook срабатывает один раз и охватывает также обычные вызовы `d()`/`kne_say()`. Исключение hook вызывает экран сбоя плагина с позицией сценария и исходными подробностями ошибки.

## UI, темы и оформление

- `RegisterPalette(PluginPalette)` добавляет вариант в настройки темы. Фон, поверхность, текст, акцент, вторичный текст и цвета групп применяются через ресурсы редактора. Палитры привязаны к открытому проекту; при недоступном расширении используется встроенная тема.
- `ApplyGamePalette(id, GameTheme)` копирует цвета в игровую палитру `custom`; её можно сохранить обычным API настроек проекта, она читается без плагина.
- `SetWorkspaceTexture(path)` применяет PNG к рабочему полю. `SetGameTexture(path)` копирует PNG в проект и задаёт начальный игровой фон; сценарий может заменить его позднее.
- `RegisterTab(PluginEditorTab)` добавляет открываемую и закрываемую вкладку с WPF-содержимым. `RegisterCommand(PluginEditorCommand)` добавляет кнопку toolbar либо пункт `context`. Фабрики могут создавать собственные WPF-контролы и модели представления.
- `RegisterScreen(PluginGameScreen)` регистрирует тип игрового экрана. `ShowScreen(context, id, visible)` показывает/скрывает его поверх новеллы и сохраняет видимость в `state`. Создание происходит на игровом Dispatcher. В фабрику передаётся диагностический JSON-снимок переменных (`Globals`, `Frames`), который имеет лимиты размера/глубины. Для обновлений элемент реализует `IPluginScreenView.UpdateState`. В интерфейсе выводите нужные значения, а авторитетные игровые данные храните в worker.

## Состояние, события и ввод

`GetJson` / `SetJson` поддерживают вложенные объекты и массивы без передачи живых Lua-ссылок. Одна запись ограничена 1 МБ. `RegisterStructure<T>(id)` и `CreateStructure(id,json)` проверяют и сериализуют пользовательские .NET-модели; в Lua это обычные таблицы, а в сохранении — JSON. `GetSaveData` / `SetSaveData` хранят данные по ключу с ID плагина.

`On(name, handler)` поддерживает `on_save`, `on_load`, `on_scene_start`, `on_text_displayed`, `on_key_press`, `on_mouse_click`. В событии есть JSON Data и текущий Context. `on_save` вызывается при явном запросе сохранения (включая игровые автосохранения), а технические снимки worker его не вызывают. `on_load` вызывается после успешного восстановления. `on_scene_start` вызывается для `main` и переходов goto/call. Текстовое событие видит уже изменённую хуком реплику.

Сохранения KNE восстанавливают историю исполнения. Сценические события, хуки и входные события воспроизводятся для восстановления тех же ветвлений. `Api.IsReplaying` позволяет пропустить внешние эффекты (HTTP, TTS, уведомления), сохраняя детерминированное изменение состояния. Регистрационные контексты нельзя использовать в обработчиках.

`InterceptInput(handler)` получает клавишу или кнопку мыши до встроенной обработки UI. Установите `Handled=true`, чтобы поглотить ввод. В UI этот callback синхронный; не выполняйте в нём длительный I/O. События ввода передаются worker отдельно, где `on_key_press` / `on_mouse_click` могут читать и менять `state`. Для автоматизации доступны также `IGameSession.InterceptInputAsync` и `NotifyPluginInputAsync`. Ввод и события записываются в историю сохранения.

## Ресурсы, сеть и звук

`Assets.Local` проверяет файл; `LoadImage` возвращает замороженный BitmapSource без удержания файлового дескриптора, уменьшает большие изображения до 4096 пикселей по большей стороне. `LoadFonts` загружает семейства из каталога TTF/OTF. `ImportLocal` переносит внешний ресурс в переносимый `.kne/plugin-assets`. Внешние папки доступны с правами текущего пользователя.

`Assets.SendAsync(HttpRequestMessage,token)` выполняет HTTP(S), возвращает байты успешного ответа, поддерживает произвольный HTTP-метод и заголовки. `DownloadAsync(url,extension,token)` сохраняет медиа в кэш проекта по хэшу. Таймаут 30 секунд, ответ/файл до 32 МБ, размер проверяется и для потоковых ответов без Content-Length. Запрос принадлежит вызывающему коду, ответ освобождается API. Сеть не вызывается автоматически.

`Media.Play(path)` возвращает отдельный аудиоканал `PluginAudio` с изменяемыми Pitch (0.5–2), Echo и Reverb (0–1), Stop/Play/Dispose. Эффекты рассчитываются в sample pipeline NAudio без повторного декодирования файла; число активных плагинных звуков ограничено 32. Это независимые каналы расширения; встроенные music/sfx не перехватываются автоматически. `Media.Speak(text, voice, rate, volume)` использует установленный системный голос Windows, `StopSpeech` останавливает TTS. Каналы и синтезатор освобождаются вместе с API.

## Редактор, анализ и перевод

`RegisterValidator` добавляет проверки в «Анализ проекта». Валидатор получает независимую копию графа и возвращает `PluginDiagnostic` с сообщением, ID узла и уровнем. До 1000 записей от одной проверки. Исключение валидатора попадает в отчёт. Игровые сценарии при анализе не запускаются; пользовательские валидаторы выполняют доверенный код.

`PluginEditorContext.GetGraph` возвращает копию открытой схемы; `ReplaceGraph` проверяет структуру и применяет весь результат одной отменяемой правкой. Через `RegisterCommand` можно создавать генераторы и добавлять связанные блоки. Тип файла (сценарий/шейдер) генератор менять не может.

`PluginDialogues.Read` извлекает реплики со стабильными ID. `Export` поддерживает JSON, DOCX и PDF с Unicode и автоматическими страницами. `Import` поддерживает JSON/DOCX; `Apply` меняет только текст и спикера, проверяет ID и не меняет исходный граф при ошибке. PDF — документ для чтения, не формат обратного импорта. `RegisterDialogueFormat` добавляет свои импортёр и экспортёр. `Api.ExportDialogues` / `ImportDialogues` используют зарегистрированные форматы и встроенные fallback. В редакторе доступно «Диалоги / переводы» для открытой блок-схемы. Записи ограничены 10000 строками и 2 млн символов, входной файл — 16 МБ.

## Lua

Lua-манифест получает таблицу `kne`: `register_group(json)`, `register_block(json,functionName)`, `register_palette(json)`, `before_text(functionName)`, `on(event,functionName)`, `http_get(url)`, `download(url,extension)`, `speak(text)`, а также флаги `is_editor` и `is_player`. Именованные callback-функции объявляются перед регистрацией. Блок получает JSON-строку и возвращает номер выхода от 1; hook текста получает `(text,speaker)` и возвращает изменённые строки; событие получает JSON Data. В worker Lua использует ту же `state`, что и игра. WPF-вкладки и пользовательские .NET-типы регистрируются через C# API.

## Рабочие примеры

Скопируйте файлы из [examples/plugins](../examples/plugins) в `plugins` вашего проекта и откройте проект заново. C#-пример добавляет квест, типизированные данные, палитру, вкладку, генератор, валидатор, игровой экран и сохранение данных. Lua-пример добавляет счётчик и перевод текста. Примеры не запрашивают повышение прав и не обращаются к сети.
