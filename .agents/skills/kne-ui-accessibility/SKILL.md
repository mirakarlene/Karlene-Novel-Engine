# Доступность UI KNE

Прочитай [AGENTS.md](../../../AGENTS.md). Проверяй затронутый сценарий. Предлагай изменения визуального состояния, состава элементов и способа взаимодействия отдельно, если пользователь их явно не запросил. При неоднозначном варианте исправления покажи пользователю выбор, сохранив существующий интерфейс до решения. Замечание аудита не расширяет объём правки.

## Проверка сценария

1. Пройди основное действие с клавиатуры. Проверь порядок `Tab` и `Shift+Tab`, видимый фокус, подходящие клавиши активации и возврат фокуса после закрытия модального окна или перехода со вложенного экрана. Для элемента с перетаскиванием проверь уже предусмотренный альтернативный путь, а при его отсутствии опиши затронутое действие.
2. На затронутых контролах проверь имя, роль и состояние в Windows UI Automation. Для кнопок со значками проверь `AutomationProperties.Name`. Для нестандартных контролов проверяй представление через `AutomationPeer`, когда оно относится к правке. Проверку с экранным диктором указывай отдельно.
3. Проверь читаемость подписей и фокуса в применимых палитрах KNE. В редакторе блок-схем проверь различимость категории по форме, значку или подписи, а также по цвету. Учитывай выбранный режим коррекции цветов и проверь, что его переключение сохраняет рабочее состояние редактора.

## Тесты KNE

- [AccessibilityUiTests](../../../tests/KNE.Tests/AccessibilityUiTests.cs) проверяет расположение доступных настроек и сохранение выбранного режима.
- [AccessibilityPresentationTests](../../../tests/KNE.Tests/AccessibilityPresentationTests.cs) проверяет цветовые преобразования, значки и имена категорий, контрастные обводки и переключение режима в работающем редакторе.
- Для минимального размера, длинных подписей и проверки действий на экране используй [kne-ui-verification](../kne-ui-verification/SKILL.md).

~~~powershell
dotnet test tests/KNE.Tests/KNE.Tests.csproj -c Release --filter 'FullyQualifiedName~KNE.Tests.AccessibilityUiTests|FullyQualifiedName~KNE.Tests.AccessibilityPresentationTests'
~~~

В замечании назови место, действие, ожидаемый и фактический результат. Напиши, что подтверждено тестом, что проверено в интерфейсе и какие сценарии с клавиатурой или диктором ещё требуют проверки.

Источники подхода — [Better Accessibility](https://usedeft.dev/skills/jakubkrehel/better-accessibility) и [рекомендации Microsoft для WPF](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/accessibility-best-practices).
